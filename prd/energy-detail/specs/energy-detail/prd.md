# 1. 背景与用户故事

用户已养成每天打开 App 先看精力分的习惯，但首页只展示精力总分（0–100）和睡眠 / 小睡 / 运动三个因子的加减分，无法回答用户最直接的疑问——"为什么今天 72 而不是 90？是睡少了还是运动过头了？睡眠 +85 到底哪里好哪里差？"

精力详情页承担"二级归因"角色：把首页精力卡的下钻动作接住，向用户解释三大因子各自加减了多少分；并把权重最大的睡眠因子展开成 4 个子维度（睡眠时长 / 睡眠债 / 静息心率 / 睡眠一致性），分别给出实际数值和"完美 / 良好 / 需注意 / 严重影响" 4 档评价。睡眠时长跳睡眠详情页、静息心率与睡眠一致性各有独立详情页；睡眠债的独立详情页尚未排期，先临时跳转到睡眠详情页，后续替换。

除日视图的归因之外，本页还提供周 / 月柱状图，让用户横向对比"这周状态最好的是哪一天"。整个页面顶部复用 HealthDetailBasePage 的返回 + 日/周/月 tab + 日期切换器组件，与其他健康二级页保持一致的视觉与交互。精力计算模型已在服务端运行，本需求不新增算法、不涉及硬件。

# 3. AC 概览

这页一共承诺 15 件事：**核心**是日视图的精力值 + 三大因子归因 + 睡眠 4 子维度展示与跳转（AC-01 ~ AC-04），以及周 / 月柱状图的趋势对比（AC-05）；**边界**覆盖整日无数据、部分因子缺失、周月空日不可选三类（AC-06 / AC-07）；**交互**覆盖日期切换、视图切换、柱状图选中、前台数据刷新、下拉刷新（AC-08 ~ AC-11 / AC-14）；**降级**覆盖加载骨架、缓存态提示、部分接口失败三类（AC-12 / AC-13 / AC-15）。

完整列表见 [acceptance-criteria.yaml](acceptance-criteria.yaml)。

# 6. Glossary（中英对照）

| 中文 | 英文 ID | 说明 |
|------|---------|------|
| 精力值 | energy_score | 当日综合精力评分，上限 100 |
| 评价档位 | energy_rating / rating_tier | 对精力值或子维度表现的定性评价（perfect / good / normal/warn / bad） |
| 归因因子 | contributor | 影响精力的三大因子：睡眠（sleep） / 小睡（nap） / 运动（exercise） |
| 子维度 | sub_dimension | 睡眠下的 4 个细分指标：duration / sleep_debt / resting_hr / consistency |
| 静息心率基线 | resting_hr_baseline | 过去 14 天静息心率均值；新用户不足 14 天数据时不显示评价 |
