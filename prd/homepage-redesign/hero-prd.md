# iSho 首页 Hero · 事件驱动状态表达 PRD

**版本** v1.0 · 2026-04-22
**归属** 首页重构子项目（见 `homepage-master-prd.md` v1.1）
**范围** 仅首页 Hero 模块。不涉及事件流、数据卡片、二级归因页、Agent 对话。
**读者** 产品 / 设计 / 研发

---

## 1 · 一句话问题

用户打开 iSho 首页，想在一眼之内知道两件事：

1. **我今天整体的头脑清晰状态如何？**
2. **此刻我正在经历什么，它会如何影响我？**

Hero 必须用最少的元素同时答掉这两个问题，且在一天中保持表达节奏一致。

---

## 2 · Hero 的职能边界

| Hero 回答 | Hero 不回答 | 不回答的那些去哪里 |
|---|---|---|
| 是什么 · 今日数字 | 为什么是这个数字 | 二级归因页（点 Hero 进入） |
| 此刻在哪 · 当前阶段 | 接下来我该做什么 | Agent 对话（点事件卡片进入） |
| 刚发生了什么 · 关键事件 | 全部事件流水 | 事件流轮播（Hero 下方独立模块） |

Hero 是"**状态**"的表达位，不是"归因"或"行动"的表达位。

---

## 3 · Hero 的四个表达位

| # | 表达位 | 内容 | 更新频率 |
|---|---|---|---|
| 1 | 数字 | 今日头脑清晰时长（如 `7h 29min`） | 全天一个值，不递减 |
| 2 | 副标题 | 固定文案 `今日头脑清晰时长` | 永不变 |
| 3 | 分档 | `低` / `一般` / `良好` / `卓越`（绝对区间） | 全天一个值 |
| 4 | **此刻状态行**（新增） | 一行自然句，由"当前阶段 + 最近关键事件"组合 | 每条关键事件写入时刷新 |

前三位是**今日总评**——回答"我拥有多少"。
第四位是**此刻状态**——回答"我正在经历什么"。

**气场色 / 光晕**视作装饰层，跟随分档自动联动（不单列为表达位）。

---

## 4 · 状态模型

Hero 的"此刻状态"由三个变量联合决定：

```
Hero 此刻状态 = f(今日数字, 当前阶段, 最近关键事件)
```

| 变量 | 取值 | 更新时机 | 映射到 |
|---|---|---|---|
| 今日数字 | `Xh Ymin` | 每日清晨一次性计算 | 表达位 1 |
| 分档 | 低 / 一般 / 良好 / 卓越 | 数字落段自动映射 | 表达位 3 |
| 当前阶段 | 夜间 / 清晨 / 上午高能 / 过渡期 / 午后高能 / 傍晚过渡 / 夜晚（共 7 段） | 时钟自然推进 | 表达位 4 |
| 最近关键事件 | 事件流中最接近"此刻"且 impact 非"轻微"的一条 | 每条关键事件写入时 | 表达位 4 |

---

## 5 · "此刻状态行" 生成规则

**取数优先级**（从上往下，命中即停）：

1. **正在经历的关键事件**（state = in_progress 且 impact 非"影响轻微"）→ 使用"进行式"模板
2. **30 分钟内刚完成的关键事件**（state = just_completed 且 impact 非"影响轻微"）→ 使用"完成式"模板
3. **当前阶段**（30 分钟内无事件时）→ 使用"阶段式"模板

**边界约束**：

- 未来计划事件（scheduled）**不参与** Hero 状态行
- 数据波动事件（HRV 骤降 / 心率异常等）**不参与**（那是归因素材，不是用户动作）
- 若最近事件 impact 被标注为"轻微"，跳过它，继续向前取
- 若 2 小时内都无合规事件，退到阶段式文案
- 一次只取 1 条，不做多条拼接

**文案长度**：单行不超过 **18 个汉字 / 24 个英文字符**，超过则截断省略号由设计兜底。

## 6 · 文案库

### 6.1 阶段式（无事件时的兜底）

| 当前阶段 | 此刻状态行 |
|---|---|
| 夜间（00:00-06:00） | `夜间休息中` |
| 清晨（06:00-10:00） | `上午高能期即将开始` |
| 上午高能（10:00-12:00） | `上午高能期进行中` |
| 过渡期（12:00-15:30） | `午后过渡 · 下一段 15:30 开始` |
| 午后高能（15:30-17:00） | `下午高能期进行中` |
| 傍晚过渡（17:00-21:00） | `今日高能已累积完` |
| 夜晚（21:00-24:00） | `准备进入夜间休息` |

*时间段为示意，实际由用户基线决定，Hero 只负责展示。*

### 6.2 事件驱动式 · 完成式（"刚完成…"）

| 事件类型 · 子类 | 此刻状态行（完成 30 min 内） |
|---|---|
| sleep · 夜间睡眠 | `昨夜睡眠 {duration} · 恢复良好` / `恢复一般` / `恢复较浅` |
| sleep · 午睡 | `刚完成 {duration} 午睡` |
| intake · 咖啡 | `刚喝完咖啡 · 醒神窗口打开` |
| intake · 餐食 | `刚完成{餐名}` |
| intake · 酒精 | `已摄入酒精 · 夜间影响将显现` |
| exercise · 有氧 | `刚完成 {duration} 有氧` |
| exercise · HIIT | `刚完成 HIIT · 修复进行中` |
| activity · 深度工作 | `深度工作段刚结束` |
| regulation · 冥想 | `冥想刚结束 · HRV 回正` |
| regulation · 呼吸练习 | `呼吸练习刚结束` |
| task · 计划任务 | `刚完成计划任务` |

### 6.3 事件驱动式 · 进行式（"正在…"）

| 事件类型 · 子类 | 此刻状态行（in_progress） |
|---|---|
| sleep · 午睡 | `午睡中` |
| intake · 餐食 | `用餐中` |
| exercise · 有氧 | `{运动名}中` |
| activity · 深度工作 | `深度工作中` |
| regulation · 冥想 | `冥想中` |

（完成式 = 事件已结束但其"余波"仍定义此刻；进行式 = 事件正在发生，此刻被事件占据。两者互斥，状态行在两者之间切换。）

### 6.4 数字与分档的语言规范

| 规则 | 示例（允许） | 反例（禁止） |
|---|---|---|
| 数字读法 | `7h 29min` / `6h 10min` | `7.5 小时` / `450 分钟` |
| 分档文字 | `良好` | `良好 82%` / `良好（较昨日 ↑）` |
| 禁用表达 | — | `剩余 Xh` / `还差 Xh` / `已消耗 Y%` / `较昨日 ↑/↓` |

## 7 · 不做清单（硬约束）

| Hero 不做 | 理由 |
|---|---|
| 数字随时间递减或倒计时 | 正面框架：传递"拥有多少"而非"剩多少"（Master PRD L2 共识） |
| 分档用进度条 / 百分比 / 差值 | 绝对分档足够；进度条是电量心智残留 |
| 副标题写叙事化文案（如 `昨晚睡得还不错`） | 副标题固定为功能说明，不代言用户感受 |
| 状态行写因果断言（如 `因为午睡所以下午会更好`） | 因果归因放二级页；Hero 只描述事实 |
| 状态行写行动建议（如 `建议午后喝杯咖啡`） | 建议走事件卡片的 "Ask Isho" 入口；Hero 不做教练 |
| 响应数据波动事件（如 HRV 骤降） | 数据波动是归因素材，不是用户动作；不入 Hero |
| 响应未来计划事件（scheduled） | 状态只反映已发生或正在发生，不预告 |
| 同时拼接多条事件 | 多主角 = 无主角；状态行一次只有 1 条主信息 |

## 8 · 五个典型时刻 · 状态样例

| 时刻 | 情境 | 数字 | 分档 | 此刻状态行 |
|---|---|---|---|---|
| 09:30 · 晨起 | 昨夜睡眠刚结束 30 分钟内 | 7h 29min | 良好 | `昨夜睡眠 7h12 · 恢复良好` |
| 12:45 · 午餐刚结束 | 上午高能期结束、午餐结束 20 分钟 | 7h 29min | 良好 | `刚完成午餐` |
| 14:30 · 午睡刚结束 | 30 min 午睡结束 10 分钟 | 7h 29min | 良好 | `刚完成 30 分钟午睡` |
| 18:35 · 下午深度工作结束 | 下午高能期结束、深度工作刚结束 | 7h 29min | 良好 | `深度工作段刚结束` |
| 21:10 · 夜间冥想 | 冥想结束、进入夜晚过渡 | 7h 29min | 良好 | `冥想刚结束 · HRV 回正` |

**一致性检查**：五个时刻的 Hero 主体结构完全相同（数字 + 副标题 + 分档 + 状态行），只有状态行文案变化 —— 与 Master PRD "结构一致" 硬约束一致。

## 9 · 与其他模块的关系

| 模块 | 关系 |
|---|---|
| `homepage-master-prd.md` v1.1 | Hero PRD 是其 L2 "核心指标" + L3 "首屏结构" 中 Hero 部分的细化。Master 中的 `Hero 分档评价规则` 维持不变，本 PRD 额外定义表达位 4（状态行）。 |
| `today-tab-prd.md` Event 实体 | Hero 状态行所依赖的"最近关键事件"是同一份 Event 数据的读取视图，不新增实体。 |
| 事件流（Event Stream 轮播） | 事件流仍列出全部事件；Hero 只吸收其中"最关键一条"做摘要。两者信息层级不同：Hero = 一句话状态；事件流 = 可滑动查看的完整事实列表。 |
| 二级归因页 | 点击 Hero 数字 / 分档进入，回答"为什么今日是这个数字"。本 PRD 不定义。 |
