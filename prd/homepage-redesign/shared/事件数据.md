# iSho 首页事件表 · 统一字段与示例

**版本** v1.4 · 2026-04-23
**变更摘要**（v1.3 → v1.4）：
- `headline` / `narrative` / `prompts` 三个**文案字段**扩为 **日/夜两版**（`.day` / `.night`）——由 event-attribution 模块在日/夜 mode 切换时取对应版本（详见 §2.2）
- 新增 `ingested_at` 字段——事件进入本地存储的时间戳，供 event-attribution 冷启动游标判新
- 新增 §2.2「日 / 夜两版文案规范」：说明两版语义差异 + 生成分工（`headline` 规则生成 / `narrative` + `prompts` LLM 生成）
- 新增 §2.3「headline 状态档位规范」：句式风格 + 日夜两版关系 + 夜间睡眠 12 档表 + 午睡 5 档表 + 运动后缀决定规则 + 运动强度计算公式（HRmax 估算 / 心率分区 / 派生特征）+ 步行表 + 运动表（合并 moderate + vigorous）；9 条示例 headline 全部按新表重判
- §3 示例陆续扩充为两版（v1.4 先补 3.1 夜间睡眠 · 充分恢复、3.9 运动 · 高强度；3.7 步行 / 3.8 中低强度 / 3.9 运动夜版随 §2.3 扩充已补齐两版 headline；其余 5 条睡眠 headline 已重判但 narrative / prompts 仍单版，随 event-attribution 联调逐条补齐两版叙事）

**范围** 仅 Apple Watch 可自动识别（HealthKit 自动写入）的事件。
**不收** 需要用户在 iSho 内手动录入的事件（咖啡 / 餐食 / 酒精 / 深度工作 / 任务等）——后续若接入手动录入能力再扩充。
**不收** 正念类（呼吸练习 / 冥想）—— v1.1 临时移出，避免与运动类在 impact 语义上重叠。
**不收** 数据波动事件（HRV 骤降 / 心率异常）—— 按 Master PRD 共识，这类是归因素材，不是事件流入口。

## 1 · 事件分类（过滤后）

| 大类 | 子类 | Apple Watch 采集方式 |
|---|---|---|
| **睡眠** | `night_sleep` · 夜间睡眠 | Sleep 应用自动记录（戴表入睡即写入 HealthKit） |
| **睡眠** | `nap` · 午睡 | watchOS 9+ 日间睡眠自动检测 |
| **运动** | `walking` · 步行 | Workout 自动开始 / Activity 累计 |
| **运动** | `moderate` · 中低强度 | Workout 自动开始（心率稳定在 Z2，如慢跑 / 骑行 / 泳池） |
| **运动** | `vigorous` · 高强度 | Workout 自动开始（心率峰值进入 Z4–Z5，如冲刺 / HIIT / 力量） |

**共 2 大类 · 5 子类**。

**子类收敛原则**：
- 不按器械 / 动作细分（不把跑步 / 骑行 / 游泳 / HIIT / 瑜伽列为独立子类），而是按**心率强度区间**归并 —— 因为 Hero 层关心的只是"对今日高能的影响"，这由强度而非器械决定。
- 睡眠保留 2 子类（夜间 / 午睡），因为两者的 impact 语义完全不同（夜间睡眠 = 定义 Hero 基线；午睡 = delta）。夜间睡眠的好/坏通过示例数据表达，不再分子类。

## 2 · 统一字段（所有事件共用）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 事件唯一标识（系统生成） |
| `category` | enum | ✅ | `sleep` / `exercise` / `mindfulness` |
| `subtype` | string | ✅ | 子类键（如 `night_sleep` / `outdoor_run` / `breathing`） |
| `title` | string | ✅ | 事件标题（事件流卡片展示用，如 `昨夜睡眠` / `中低强度运动`） |
| `display_name` | string | ✅ | Hero 状态行用的中文名。睡眠固定 `夜间睡眠` / `午睡`；运动直接取 HealthKit `HKWorkoutActivityType` 的中文映射（`跑步` / `骑行` / `游泳` / `HIIT` / `瑜伽` / `功能性训练` / `步行` 等）。与 `title` 的差异：`title` 按 subtype 归类粗描述，`display_name` 按 HealthKit 原始类型细描述，Hero 偏细、事件卡片偏粗。 |
| `state` | enum | ✅ | `in_progress`（正在进行） / `just_completed`（刚刚完成，30 min 内） |
| `start_at` | datetime | ✅ | 事件开始时间 |
| `end_at` | datetime | state=just_completed 必填 | 事件结束时间 |
| `duration` | string | ✅ | 人类可读时长（如 `7h 12min` / `32 min`） |
| `source` | enum | ✅ | 数据来源（`healthkit.sleep` / `healthkit.workout`） |
| `impact` | string[] | ✅ | 对两个指标的影响，每条形如 `{指标} {值}`，至多 2 条。详见下方格式说明。 |
| `headline.day` / `headline.night` | string | ✅ | L4 结论一句话（**两版**；≤ 12 字；日间归因到高能时长、夜间归因到入睡准备度）详见 §2.2 |
| `narrative.day` / `narrative.night` | string | ✅ | 1–2 句归因叙述（**两版**；≤ 71 字）详见 §2.2 |
| `prompts.day[]` / `prompts.night[]` | string[] | ✅ | 1–3 条推荐提问（**两版**；每条 ≤ 10 字；点击进 Agent 对话）详见 §2.2 |
| `ingested_at` | datetime | ✅ | 事件进入本地存储的时间戳（非 HealthKit 原始 `start_at` / `end_at`）；供 event-attribution 冷启动游标判新（`ingested_at > last_cold_start_at` 视为"本次区间的新事件"） |

**所有字段共用一张表，不再按类别分化**。

### `impact` 字段格式

页面上的影响表达**只有两种指标** + **值变化**，别的一律不写：

| 指标 | 单位 | 变化形式 |
|---|---|---|
| `高能时长` | 小时/分钟 | 绝对值（`7h 29min`）或 delta（`+20min` / `-15min`） |
| `入睡准备度` | 百分比 | 绝对值（`82%`）或 delta（`+6%` / `-8%`） |

**取值规则**：

- **source 事件**（夜间睡眠）：用绝对值，表示该事件**定义**了今日指标（如 `高能时长 7h 29min`）
- **非 source 事件**：用 delta，显式带正负号（如 `入睡准备度 -6%`）
- **多条并列**：一个事件最多写 2 条，一条指标一行
- **低于阈值**：不写指标，用占位文案 `影响轻微`（单条）
- 不写任何辅助文字（不写"预计"/"约"/"延长"/"压低"等动词修饰）—— 这些语义通过 `narrative` 解释

## 2.1 · Event icon 映射（跨 UI 模块共享）

所有消费本契约的 UI 模块（`energy-detail` / `event-attribution` / 未来 `hero` 若需 icon），**必须**共用以下 5 类 icon token——不在各模块各自定义。v1 icon 维度刻意少于 subtype 维度（把运动强度归并），因为 icon 是用户直觉识别，subtype 是数据粒度，两者服务不同目标。

| icon token | 中文名 | 对应 subtype | 说明 |
|---|---|---|---|
| `sleep` | 夜间睡眠 | `night_sleep` | 与 `nap` 区分，两者 impact 语义不同（sleep 定义基线、nap 是 delta） |
| `nap` | 小睡 | `nap` | 不合并到 `sleep`——用户心智里两者不同事件 |
| `exercise` | 运动 | `moderate` + `vigorous` | 合并中强度 / 高强度为一个 icon；强度差异由事件卡片的 `headline` / `narrative` 表达，不由 icon 表达 |
| `walking` | 走路 | `walking` | 从 `exercise` 拆出——走路是日常活动、不是"锻炼"心智；用户行为上与运动区分清晰 |
| `common` | 常规事件 | 其他 / custom | 非前 4 类的通用兜底 icon；v2+ 扩展 `intake` / `regulation` / `task` 等类前统一走此槽 |

### 命名约束

- **英文 token 不与 subtype 完全同名**：icon 维度是 UI 视觉分类，与 subtype 数据粒度解耦——维度演化时不互相绑架
- **"常规事件" 不叫 `fallback` / `other` / `custom`**：避免误导用户看到 icon 就以为是"未分类"；`common` = "不在前 4 类专属视觉里的日常事件"，语义更稳
- **子类 / 强度差异不由 icon 表达**：事件卡片的 `title` / `headline` / `narrative` 承担细粒度，icon 只负责一眼识别

## 2.2 · 日 / 夜两版文案规范

同一个 Event 实体的 `headline` / `narrative` / `prompts` 字段各有**日间版与夜间版**——消费方（`event-attribution` 模块）在 [hero](../modules/hero/开发文档.md) mode 切换时选对应版本渲染。

### 2.2.1 两版语义差异

| 版本 | 归因维度 | 用户关心的问题 | 文案角度 |
|---|---|---|---|
| `.day` | **高能时长** | "这次事件让我今天清醒 / 迟缓多久？" | 生理指标 → 今日头脑清晰度 |
| `.night` | **入睡准备度** | "这次事件会让我今晚好入睡 / 难入睡吗？" | 生理指标 → 今晚入睡状态 |

**同一组生理指标，两套归因语言**：比如一次 17:30 完成的高强度运动——
- `.day`：讲"EPOC 约 90 min，核心体温回升延长了下午高能尾段" → 归因到今日清醒度的延续
- `.night`：讲"核心体温升高 0.8°C，交感神经兴奋尚未回落" → 归因到今晚入睡的推迟

### 2.2.2 生成分工

| 字段 | 生成方 | 稳定性 |
|---|---|---|
| `headline.day` / `headline.night` | **上游事件流服务** · 规则模板 | 同一事件多次读取**稳定不变**；规则生成，可端侧缓存 |
| `narrative.day` / `narrative.night` | **LLM 文案生成服务** · 大模型生成 | 同一事件多次读取**可能略异**；保证语义稳定、遵守 §3 写作标准、不超长（71 字） |
| `prompts.day[]` / `prompts.night[]` | **LLM 文案生成服务** · 大模型生成 | 条数 1-3 条不保证次次相同；单条不超 10 字 |

### 2.2.3 字段缺失降级

| 情况 | 端侧降级 |
|---|---|
| 只有 `.day` 有值、`.night` 缺失 | 夜间 mode 下该事件卡**整卡从 `current_batch` 剔除**——不能用日间版冒充夜间 |
| `narrative.day/.night` 空字符串 | 卡片该行**整行隐藏**，其他槽位正常 |
| `prompts.day/.night` 空数组 | chips 区**整块隐藏**，卡片其他槽位正常 |
| `headline.day/.night` 缺失 | 整卡从 `current_batch` 剔除（归因大标题是核心，缺失 = 事件不可呈现） |

### 2.2.4 写作硬约束（两版共通）

- 同一事件的 `.day` / `.night` 两版**针对同一组生理指标**撰写——不允许一版写"深睡占比 22%"、另一版换个指标写"睡眠效率 91%"
- 两版**分别独立**遵守主文档 §L4 Do / Don't：不代言感受 / 不因果断言 / 不给行动建议 / 禁止伪术语
- 长度上限按 [shared/文案长度.md](./文案长度.md)；两版各自判长，不共享字数预算

## 2.3 · headline 状态档位规范

`headline` 是事件的**整体定性句**——读者扫一眼即可知该事件好/中/差以及为什么。本节定义全部允许的 headline 文案，由上游事件流服务按下表**封闭枚举**产出，不另起文案变体。

### 2.3.1 文案风格

- 句式：**`{客观特征 + 温和方向感} 的 {事件短指代}`**（一句话讲完，不用 `·` 切分）
- 末尾事件短指代：睡眠类用「一夜」/「小睡」；运动类用「步行」/「有氧」/「冲刺」/「高强度」（运动 3 类待 v1.4.1 扩充时定稿）
- 方向感词限定温和量化词库：连续 / 完整 / 稳定 / 满分 / 充分 / 偏少 / 偏晚 / 偏短 / 偏长 / 明显 / 严重
- ❌ 禁止代言感受（"睡得不踏实"）/ 因果断言 / 行动建议 / 伪医学术语（参见主文档 §L4）
- 字数上限 12，参考 [shared/文案长度.md](./文案长度.md)
- **不重复事件卡片其他槽位已展示的信息**——事件卡片本身已展示时长 / 时段 / impact 数值，headline 不复述这些数据

### 2.3.2 日 / 夜两版的关系

| 子类 | `headline.day` 与 `headline.night` 的关系 |
|---|---|
| `night_sleep` · `nap` | **同一文案**（两版同步）——昨夜睡眠 / 午睡的"对今晚再入睡的预示"高度依赖于事件本身的质量描述，不另起夜间归因角度 |
| `walking` · `moderate` · `vigorous` | **两版独立**——运动对今日清醒激活 vs 对今晚入睡推迟，归因角度差异显著，分别撰写 |

### 2.3.3 夜间睡眠 `night_sleep` · 状态优先级表

12 档 + 兜底；上游事件流服务按优先级**自上而下**匹配，命中即出 headline，不复合多档。

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 严重不足 | 时长 < 5h | 明显欠睡的一夜 |
| 2 | 早醒 | 结束 < 05:30 且 时长 < 7h | 早醒的一夜 |
| 3 | 入睡明显偏晚 | 入睡 > 01:00 且 时长 < 6h | 入睡明显偏晚的一夜 |
| 4 | 频繁觉醒 | 觉醒次数 ≥ 3 | {N} 次觉醒的一夜 |
| 5 | HRV 明显偏低 | HRV 低于基线 > 15ms 且 时长 ≥ 6h | HRV 明显偏低的一夜 |
| 6 | 深睡偏少 | 时长 ≥ 6h 且 深睡比 < 15% | 深睡偏少的一夜 |
| 7 | 时长偏短 | 5h ≤ 时长 < 6.5h 且 其他指标无异常 | 时长偏短的一夜 |
| 8 | 入睡偏晚但时长够 | 入睡 > 01:00 且 时长 ≥ 6h | 入睡偏晚但时长够的一夜 |
| 9 | 时长偏长 | 时长 > 9.5h | 时长明显偏长的一夜 |
| 10 | 满分 | 时长 7-9h 且 深睡比 ≥ 20% 且 觉醒 < 2 且 HRV ≥ 基线 +5ms 且 入睡潜伏期 ≤ 20min | 满分的一夜 |
| 11 | 充分恢复 | 时长 ≥ 7h 且 深睡比 ≥ 13% 且 觉醒 < 3 且 HRV ≥ 基线 -10ms | 连续完整的一夜 |
| 12 | 基本到位（兜底） | 不命中以上 | 时长达标的一夜 |

**动态填槽**：状态 4 的 `{N}` 填实际觉醒次数；觉醒 ≥ 5 次封顶为 "5+ 次觉醒的一夜"。

### 2.3.4 午睡 `nap` · 状态优先级表

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 误入深睡 | 时长 ≥ 40min 且 进入 N3 深睡 | {N} min 的过深小睡 |
| 2 | 时长偏长 | 时长 ≥ 60min 且 未进入深睡 | 时长偏长的小睡 |
| 3 | 几乎未睡 | 时长 < 10min 或 全程未进入睡眠阶段 | 几乎未入睡的小睡 |
| 4 | 标准浅睡 | 20-40min 且 全程 N1-N2 | 未进入深睡的小睡 |
| 5 | 短小提神（兜底） | 不命中以上（如 10-20min 浅睡 / 其他组合） | 短小提神的小睡 |

**动态填槽**：状态 1 的 `{N}` 填实际午睡分钟数（向下取整）。

### 2.3.5 运动事件的后缀决定规则

合并 `moderate` + `vigorous` 为「运动」一个大类（HealthKit 不区分中低 / 高强度，由 iSho 端按心率推算）。`walking` 单独分类。

| 事件 | headline 末尾后缀 |
|---|---|
| `subtype = walking` | **步行** |
| `subtype = moderate / vigorous` 且 `display_name = 跑步` | **跑步** |
| `subtype = moderate / vigorous` 且 `display_name` 为其他（骑行 / 游泳 / HIIT / 瑜伽 / 力量训练 等） | **运动** |

### 2.3.6 运动强度计算公式

强度判定**不能用平均心率**——一次 1h 跑里 10min 冲刺也是高强度运动；平均心率会把冲刺段稀释。改用**心率序列分区间累计时长**判定。

#### 输入数据（全部来自 HealthKit 直出）

| 字段 | HealthKit 来源 |
|---|---|
| `birthDate` | `HKCharacteristicType.dateOfBirth` |
| workout 期间心率序列 | `HKQuantityTypeIdentifier.heartRate`（按秒采样） |
| `start_at` / `end_at` | workout 实例属性 |
| `display_name` | `HKWorkoutActivityType` 中文映射（跑步 / 骑行 / HIIT / 瑜伽 / ...） |

#### 第 1 步 · 估算个人最大心率 HRmax

```
age = 当前年份 - birthDate.year
HRmax = 220 - age          # 经典 Fox 公式
```

- 若 `birthDate` 不可得（用户未授权 / 未填）→ 默认 `age = 30`，`HRmax = 190`
- 后续阈值按 `% HRmax` 表达，自动随用户年龄个性化

#### 第 2 步 · 心率序列按分钟聚合

将 workout 期间的心率序列按"分钟"重采样（每分钟取该分钟内所有采样值的均值），得到长度 = workout 总分钟数的心率序列 `hr_minute_series[]`。

#### 第 3 步 · 心率区间定义（按 HRmax 百分比）

| 区间名 | 阈值 | 通俗含义 |
|---|---|---|
| **高强度区** | ≥ 80% HRmax | 接近无氧 / 冲刺 |
| **中高强度区** | 65-80% HRmax | 持续有氧上限 |
| **中等强度区** | 50-65% HRmax | 持续有氧适中 |
| **轻松区** | < 50% HRmax | 日常活动 |

#### 第 4 步 · 派生强度特征

| 特征名 | 计算 | 用途 |
|---|---|---|
| `peak_hr_pct` | `max(hr_minute_series) / HRmax` | 判"全力冲刺"档 |
| `high_intensity_min` | hr_minute_series 落在高强度区的累计分钟 | 判"含高强度段" |
| `moderate_high_min` | 落在中高强度区的累计分钟 | 判"持续偏强" |
| `moderate_min` | 落在中等强度区的累计分钟 | 判"持续中等 / 黄金强度" |
| `easy_min` | 落在轻松区的累计分钟 | 判兜底"强度略低" |
| `total_min` | workout 总时长分钟数 | 联合判"漂亮的一次"档 |
| `intervals_count` | hr_minute_series 中"心率从 < 65% HRmax 反复跨越到 ≥ 65% HRmax"的段数 | 判"多段间歇 HIIT" |

#### 第 5 步 · 派生时点特征（夜 mode 用）

| 特征名 | 计算 |
|---|---|
| `usual_bedtime` | 用户近 14 日 `night_sleep.start_at` 的中位数（hh:mm）；若数据不足 14 日 → 取已有数据中位数；若无任何睡眠数据 → 兜底 `23:00` |
| `hours_to_bedtime` | `event.end_at` 到下一个 `usual_bedtime` 时刻的小时差（向下取整到 0.1h） |

### 2.3.7 步行 `walking` · 状态优先级表

#### 日 mode

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 漂亮的一次步行（成就感） | `moderate_min + moderate_high_min ≥ 30` 且 `total_min ≥ 45` | 漂亮的一次步行 |
| 2 | 节奏明快 | `moderate_min + moderate_high_min ≥ 10` 且 `total_min < 45` | 节奏明快的步行 |
| 3 | 略有起伏 | `moderate_min ≥ 5` | 略有起伏的步行 |
| 4 | 轻松散步（兜底） | 全程在轻松区 | 轻松节奏的步行 |

#### 夜 mode

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 略影响入睡 | `hours_to_bedtime < 1` 且 `moderate_min ≥ 5` | 略影响入睡的步行 |
| 2 | 影响轻微（兜底） | 不命中以上 | 影响轻微的步行 |

### 2.3.8 运动 `moderate + vigorous` · 状态优先级表

#### 日 mode

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 多段间歇 HIIT | `display_name = HIIT` 或 `intervals_count ≥ 3` | 多段间歇的运动 |
| 2 | 全力冲刺（自带成就感） | `peak_hr_pct ≥ 90%` | 全力冲刺的{后缀} |
| 3 | 含高强度段 | `high_intensity_min ≥ 5`（不命中状态 1 / 2） | 含高强度段的{后缀} |
| 4 | 黄金强度（成就感） | `moderate_min + moderate_high_min ≥ 30` 且 `total_min ≥ 30` | 漂亮的一次{后缀} |
| 5 | 持续偏强 | `moderate_high_min ≥ 20`（不命中状态 4） | 持续偏强的{后缀} |
| 6 | 持续中等 | `moderate_min ≥ 30` | 持续中等的{后缀} |
| 7 | 短时中等 | `moderate_min` 在 5-30 之间 | 短时中等的{后缀} |
| 8 | 强度略低（兜底） | 主要在轻松区 | 强度略低的{后缀} |

#### 夜 mode

「含高强度段」= `peak_hr_pct ≥ 80%` 或 `high_intensity_min ≥ 5`；「中等以上时长」= `moderate_min + moderate_high_min`。

| 优先级 | 状态名 | 判定条件 | headline |
|---|---|---|---|
| 1 | 推迟入睡概率高 | 含高强度段 且 `hours_to_bedtime < 3` | 推迟入睡概率高的{后缀} |
| 2 | 仍可能影响入睡 | (含高强度段 且 `hours_to_bedtime` 在 3-6) 或 (中等以上时长 ≥ 20 且 `hours_to_bedtime < 2`) | 仍可能影响入睡的{后缀} |
| 3 | 改善入睡准备度（成就感） | 中等以上时长 ≥ 20 且 不含高强度段 且 `hours_to_bedtime ≥ 2` | 改善入睡准备度的{后缀} |
| 4 | 影响有限（兜底） | 不命中以上 | 对入睡影响有限的{后缀} |

**HIIT vs 全力冲刺优先级**：状态 1 (HIIT) 排在状态 2 (全力冲刺) 之上。一次同时命中"4 段间歇"和"峰值 ≥ 90%"的事件，会被识别为「多段间歇」——HIIT 是运动结构（更特异），冲刺是结果指标。

### 2.3.9 阈值校准

本节阈值（睡眠：5h / 13% / 15% / 20% / 15ms / -10ms；运动：50% / 65% / 80% / 90% HRmax / `intervals_count ≥ 3` / `hours_to_bedtime` 1/2/3/6 等）为产品建议值，**最终值由上游事件流服务的医学顾问 / 算法团队校准**——调整时仅改阈值数字，不改本规范的状态档位结构与 headline 文案。

## 3 · 示例事件（5 子类 · 9 条示例）

**归因文案（`narrative`）写作标准**（日 / 夜两版都遵守）：

- ✅ 只陈述**客观可测事实**：时长 / 时段 / 心率 / HRV / 深睡-浅睡-REM 占比 / 觉醒次数 / EPOC
- ✅ 预测量必须显式标注："预计" / "约"
- ✅ 与个人基线比较时给出具体差值（如 `低于 14 日基线 9 ms`）
- ❌ 禁止代言感受："迟钝感" / "清醒窗口" / "甜蜜区" / "更精神"
- ❌ 禁止预算/电量语言："预算" / "消耗" / "结清" / "余量" / "透支"
- ❌ 禁止单方面因果断言："因为 X 所以 Y"（因果归入 Agent 对话）

**长度约定**：本 §3 示例中部分 `.day` / `.night` 文案可能超出 [shared/文案长度.md](./文案长度.md) 的 12 / 71 / 10 字上限——示例展示**语义风格**，非字符对齐样本；实际系统中所有文案均按该契约产出，端侧超长按末尾 `…` 截断，不向上游回写。
