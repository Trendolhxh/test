# 共享契约 · 首页文案长度规则

## 1. 适用范围

本契约约束 iSho **首页（Status Tab）所有 UI 模块**的文案长度上限与超长截断方式。所有消费方（hero / event-attribution / body-cards / energy-detail）必须按本契约统一执行——**不在各模块的 UI PRD / 开发文档里另写字数限制**。

## 2. 各元素长度限制

| 元素 | 上限 | 超长处理 | 主要消费方 |
|---|---|---|---|
| **状态行** | 20 字 | 末尾 `…` 省略 | `hero` |
| **事件名称** | 12 字 | 末尾 `…` 省略 | `event-attribution` |
| **事件大标题** | 12 字 | 末尾 `…` 省略 | `event-attribution` |
| **归因小字** | 71 字 | 末尾 `…` 省略 | `event-attribution` |
| **快捷问题（chips）** | 单条 10 字；同屏 1–3 条 | 单条末尾 `…` 省略；超 3 条不展示 | `event-attribution` |

### 2.1 字数计算规则

- **字数 = 中文字符数 + 半角英文 / 数字字符数 + 半角符号数**——全角中文标点按 1 字计；ASCII 字符按 1 字计；emoji 按 1 字计
- **字数判断在文案落地后**——如文案含变量（`{display_name}` / `{N}` / `{HH:MM}`）的，应按变量代入后的实际字符串长度判断
- **变量代入后超长属于内容方责任**：上游 `display_name` 传来超长内容时，由 hero / event-attribution 端按本契约截断并显示省略号，**不向上游回写抗议**

### 2.2 截断的视觉表达

- 中英 / 数字混排的省略号统一用 **U+2026（…）单字符**，不用三个英文点 `...`
- 截断点应**优先按字符边界**而非字节边界（避免半截 utf-8 字符）
- 截断不分 word break——12 字硬截，不做"按词不断"的智能截断

## 3. 消费方对接清单

| 模块 | 消费哪几条 | 出现位置 |
|---|---|---|
| `hero` | 状态行 | UI PRD §6.3 状态行文案库（v1 锁定的 ≤15 字限制升级到本契约的 ≤20 字） |
| `event-attribution` | 事件名称 / 事件大标题 / 归因小字 / 快捷问题 | UI PRD 立项时统一引用本契约（不另写字数表） |
| `body-cards` | 不消费（卡片标题 / 数值 / 单位均为定长，不会出现动态文案截断） | — |
| `energy-detail` | v1 不消费（事件 icon 不带文字标签；顶部锚文案有变量但不会超长） | — |

## 4. Do / Don't 总则

| # | Do | Don't | 为什么 |
|---|---|---|---|
| 1 | 文案库设计阶段就按本契约的字数预算 | 设计完才发现超长再回头压缩 | 截断后的文案"歧义化 / 信息丢失" |
| 2 | 变量代入超长按本契约截断 + `…` | 自行折行 / 缩小字号 / 换行成 2 行 | 折行 / 变字号会破坏页面节律与视觉等级 |
| 3 | 快捷问题超过 3 条直接不显示多余的 | 滚动横划查看更多 chip | 多 chip 横滚违反"克制 / 渐进披露"主文档约束 |
| 4 | 字数限制按本契约统一表 | 各模块在自己 PRD 里另写字数 | 同一上下文出现"事件大标题 12 字"和"事件大标题 16 字"两份事实 |

## 5. 未决

- [ ] **超长文案的可访问性**：被截断的文案在 VoiceOver 朗读时是否朗读完整原文还是截断后的？v1 默认朗读完整原文（与 iOS 系统行为一致）
