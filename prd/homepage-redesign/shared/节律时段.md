# 共享契约 · 节律时段（RhythmSegment）

## 1. 定义

**节律时段**是由**昼夜节律算法**对一日 24h 产出的**时序分段**。它**不是事件**（不是用户做的事、不是数据波动），是**时段的命名**。

- 来源：昼夜节律算法（外部契约「高能时长曲线」的副产物，或独立判定模块）
- 粒度：一日 24h 被切为 N 段连续时段；N 由当日曲线形态决定
- 性质：**全时段覆盖**——一日中每一分钟必属于某一档
- 与事件的关系：**正交**——节律时段是**背景层**，事件是**前景层**；事件可落在任意节律时段内

## 2. 5 档分类

| 档位 | 中文名 | 英文标识 | 语义 | 曲线典型形态 |
|---|---|---|---|---|
| 1 | 上升期 | `rising` | 精力正在爬升，尚未见顶 | 凸起量正向变化 |
| 2 | 高能期 | `high` | 精力处在一日峰段 | 凸起量持平在高位 |
| 3 | 过渡期 | `transition` | 精力正在回落（峰 → 休整） | 凸起量负向变化 |
| 4 | 休整期 | `low` | 精力处在一日低段 | 凸起量持平在低位 |
| 5 | 夜间 | `night` | 进入睡眠窗口；精力不再是主语 | 曲线可无；"入睡准备度"接管维度 |

### 2.1 命名对齐（硬约束）

- 与 hero T3 曲线式文案的 5 档语言一致（[modules/hero/界面设计.md §3.3.3](../modules/hero/界面设计.md)）
- 禁用同义口语：`午后低谷 / 下午低谷 / 早高峰 / 下午峰` —— 口语化命名在不同一天会指向不同档，不稳定
- "午后低谷期"这种口语可用在**产品沟通**与**onboarding**文本，**不得**用在 UI / 埋点 / 契约字段

### 2.2 档位数 N 的合法范围

| 当日形态 | 典型 N | 档位序列举例 |
|---|---|---|
| 标准一日 | 4–5 | `rising` → `high` → `transition` → `low` → `night` |
| 单峰日 | 3 | `rising` → `high` → `low` → `night` |
| 双峰日 | 5–6 | `rising` → `high` → `transition` → `rising` → `high` → `transition` → `night` |
| 高能分散日 | 1 | 全日 `transition`（配 hero `今日高能较分散` 文案） |

## 3. 数据模型

### 3.1 单段结构

```json
RhythmSegment {
  "phase": "rising" | "high" | "transition" | "low" | "night",
  "start_at": "HH:MM",       // 当日本地时间
  "end_at": "HH:MM",
  "display_name": "上升期"    // 对齐 §2
}
```

### 3.2 一日结构

```json
DailyRhythmSegments {
  "date": "2026-04-22",
  "segments": [RhythmSegment, ...],   // 时间正序，首尾连续，覆盖一日
  "source": "circadian_v1"            // 判定算法版本
}
```

## 4. 判定规则

- **输入**：当日高能时长曲线（连续值） + 睡眠窗口（来自 `prd/sleep-window/` 外部契约）
- **输出**：一日连续时段数组
- **边界产生**：由曲线的极值点（峰 / 谷）与睡眠窗口的起止点共同切分
- **边界平滑**：同一档连续时段短于 15 分钟应合并到相邻档（避免视觉杂乱）
- **算法归属**：独立需求，不在本 PRD 范围；待「高能时长计算定义」与「昼夜节律模型」两项外部契约立项后补锚点

## 5. 消费方

| 模块 | 消费形式 |
|---|---|
| `hero` | T3 曲线式状态文案取**当前时段** `phase` 决定选用哪一条分档文案 |
| `energy-detail` | 24h 视图以 `phase` 映射背景分档色；当前时段药丸取 `display_name` |
| `event-attribution` | 事件流的分组锚点对齐 `phase`（时段正序分组） |

## 6. Do / Don't

| # | Do | Don't | 为什么 |
|---|---|---|---|
| 1 | 英文标识 `rising / high / transition / low / night` | `peak / valley / morning / afternoon` | 英文标识与**曲线形态**耦合，不与**时间段**耦合——一天可能多次上升 |
| 2 | 中文名 上升期 / 高能期 / 过渡期 / 休整期 / 夜间 | 午后低谷 / 早高峰 / 下午峰 | 口语命名在不同一天指向不同档，不稳定 |
| 3 | `segments` 首尾连续、全日覆盖 | 存在未分类空档（如 12:00-14:00 无 phase） | 节律是全时段概念；空档迫使消费方写额外分支 |
| 4 | 15 分钟短档合并到邻档 | 一日切成 20+ 段 | 视觉杂乱，违反主文档冷静感 |
| 5 | 节律时段作为**背景层** | 节律时段作为**独立事件卡** | 节律不是事件；独立卡会与事件流竞争主角位 |
| 6 | 同一 `date` 请求两次返回一致 | 同日多次请求 `segments` 漂移 | 漂移会触发 UI 背景色抖动 |
