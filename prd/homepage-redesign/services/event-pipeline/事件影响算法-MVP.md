# 事件对两指标影响 · MVP 算法

> 本文档是事件 `impact` 字段在「高能时长」和「入睡准备度」两个维度上的 **MVP 计算逻辑直接定义**——研发可据此实现。目标：先跑通、让事件卡片能展示 impact 数值，再迭代到"全天重算"完整模型。

---

## 1. 简化决策

### 完整模型（非 MVP）

事件发生 → 高能时长计算服务**重算全天总值与时段分布** → `delta = 新总值 − 旧总值`；入睡准备度影响 → sleep-readiness 服务"事件前 vs 事件后"对比真实 delta。这需要服务触发重算、持有历史值做对比，工程成本较高。

### MVP 决策

- **不触发全天重算**；每个事件按自身特征查表产出 delta
- **多事件简单相加**；不做相互作用 / 衰减 / 协同效应
- **单事件 delta 封顶**：高能时长 `±30min` / 入睡准备度 `±15%`
- **高能时长当日累计下限** `0min`
- **vigorous / moderate 用"事件结束 → 推荐入睡时间的间隔 `Δt`"** 作为 timing 锚点
- **入睡准备度 delta 只是事件卡片的预估显示值**，不实际进入 sleep-readiness 服务计算（详见 §4.6）

## 2. 高能时长 delta

### 2.1 `night_sleep`

**不产出 delta**——直接引用高能时长计算服务当日返回的**绝对值**：

```
impact[0] = "高能时长 {Xh Ymin}"   // 例：高能时长 7h 12min
```

若高能时长计算服务结果尚未就绪：`impact = []`（空数组），等算法结果到达后由 event-pipeline 补写。

### 2.2 `walking`

**固定判定为"影响轻微"**，不产出 delta：

```
impact = ["影响轻微"]
```

### 2.3 `nap`

按"时长 × 最深睡眠阶段"分档。最深睡眠阶段从 HealthKit sleep stage 数据读取。

| 条件 | 高能时长 delta |
|---|---|
| 时长 `< 30min`，最深阶段 N1 / N2 | `+20min` |
| `30 – 60min`，最深阶段 N1 / N2 | `+25min` |
| 任意时长，最深阶段进入 N3（深睡） | `-15min` |
| 时长 `> 60min`（即使未进入 N3） | `-15min` |

### 2.4 `moderate`

按运动时长分档：

| 时长 | 高能时长 delta |
|---|---|
| `< 20min` | `+10min` |
| `20 – 45min` | `+15min` |
| `> 45min` | `+20min` |

### 2.5 `vigorous`

按"事件结束时刻到推荐入睡时间的间隔 `Δt`"分档：

| `Δt` | 高能时长 delta |
|---|---|
| `≥ 5h` | `+10min`（EPOC 延长当日尾段，正效应） |
| `2 – 5h` | `0min`（正负效应抵消） |
| `< 2h` | `-5min`（临睡交感激活，压缩尾段） |

**推荐入睡时间未就绪时**：兜底 22:30 计算 `Δt`。

---

## 3. 多事件叠加与约束（高能时长）

### 叠加
```
当日高能时长 = night_sleep 绝对值
             + (当日全部 nap / moderate / vigorous 的 delta 之和)
```

### 约束
1. **单事件 delta 范围**：`clip(delta, -30min, +30min)`
2. **当日总 delta 下限**：累计 delta ≥ `-(night_sleep 绝对值)`（保证当日高能时长 ≥ 0）
3. **night_sleep 数据缺失**：当日无 night_sleep 时，不计算其他事件的 delta 总和（事件卡片仍展示各自 impact）

## 4. 入睡准备度 delta

### 4.1 `night_sleep`

**不产出 delta**——昨夜睡眠对今晚准备度的影响已经体现在 HRV 基线 / HR 基线等个人基线上。卡片的夜间版 `headline.night` / `narrative.night` 用质性描述承担信息（如 `连续性良好 · HRV 基线稳`）。

```
impact 数组中不包含"入睡准备度 X%"条目
```

### 4.2 `walking`

**固定"影响轻微"**，不产出 delta。

### 4.3 `nap`

按"时长 × 最深睡眠阶段"分档。午睡消耗睡眠压力，对今晚准备度为**负效应**：

| 条件 | 入睡准备度 delta |
|---|---|
| 时长 `< 30min`，最深阶段 N1 / N2 | `-2%`（轻度压力消耗） |
| `30 – 60min`，最深阶段 N1 / N2 | `-5%` |
| 任意时长，最深阶段进入 N3 | `-10%`（深睡消耗压力多） |
| 时长 `> 60min`（即使未进入 N3） | `-10%` |

### 4.4 `moderate`

按 `Δt`（事件结束到推荐入睡时间的间隔）分档：

| `Δt` | 入睡准备度 delta |
|---|---|
| `≥ 5h` | 不展示（影响轻微） |
| `2 – 5h` | 不展示（影响轻微） |
| `< 2h` | `-2%`（轻度交感激活） |

### 4.5 `vigorous`

按 `Δt` 分档：

| `Δt` | 入睡准备度 delta |
|---|---|
| `≥ 5h` | 不展示（EPOC 基本消退，不产生有意义影响） |
| `2 – 5h` | `-3%` |
| `< 2h` | `-6%` |

### 4.6 显示值与实际计算的关系

本节的入睡准备度 delta 是**事件卡片的预估显示值**，不进入 sleep-readiness 服务的实际计算流程。两条路径的分工：

| 路径 | 承担职责 |
|---|---|
| **event-pipeline 产出的 delta** | 事件卡片上给用户看的"这件事大致对今晚准备度贡献了多少"（解释性 / 教学性） |
| **sleep-readiness 服务实时计算** | hero 夜间主数字展示的 `readiness_value` 权威值；按 [sleep-readiness/算法-MVP](../sleep-readiness/算法-MVP.md) 基于当前传感器数据独立计算 |

事件的真实生理影响（HR 升高、HRV 下降等）已经通过传感器读数反映在 sleep-readiness 的计算里，不需要再把本节 delta 加回去。

## 5. 多事件叠加与约束（入睡准备度）

### 叠加
```
事件卡片展示的入睡准备度总影响 = 当日全部非 night_sleep 事件的 delta 之和
```

### 约束
1. **单事件 delta 范围**：`clip(delta, -15%, +15%)`
2. **当日总 delta 范围**：`clip(累计 delta, -30%, +15%)`——避免极端场景下显示不合理的累积贡献
3. **总 delta 仅用于事件卡片堆叠展示**（如果 UI 需要）；不进入 sleep-readiness 服务

## 6. impact 字段组装示例

| subtype | impact 示例 |
|---|---|
| `night_sleep` | `["高能时长 7h 12min"]` |
| `walking` | `["影响轻微"]` |
| `nap` 浅睡 30min | `["高能时长 +20min", "入睡准备度 -2%"]` |
| `nap` 深睡 65min | `["高能时长 -15min", "入睡准备度 -10%"]` |
| `moderate` 33min 07:15 结束 | `["高能时长 +15min"]`（Δt 远 → 入睡准备度 delta 不展示） |
| `moderate` 33min 21:00 结束（Δt = 1.5h） | `["高能时长 +15min", "入睡准备度 -2%"]` |
| `vigorous` 22min 07:15 结束 | `["高能时长 +10min"]`（Δt ≥ 5h） |
| `vigorous` 22min 21:00 结束 | `["高能时长 -5min", "入睡准备度 -6%"]`（Δt < 2h） |

**规则**：
- `impact` 数组最多 2 条
- 顺序：高能时长在前 / 入睡准备度在后
- `影响轻微` 单独一条、不与其他组合
- 某指标 delta 为"不展示"时，该条目不写入数组；若两个指标都不展示，写入 `["影响轻微"]`

---

## 7. 非 MVP 范围（v2 升级路径）

待 MVP 验证后再考虑：
- 高能时长 delta 改为调用高能时长计算服务做"全天重算"
- 入睡准备度 delta 改为 sleep-readiness 服务"事件前 vs 事件后"对比的真实 delta
- 考虑事件相互作用（如 nap + 晚间 vigorous 的协同效应）
- 个性化：用户 HR / HRV 基线离散度大时，delta 幅度按敏感度系数缩放
