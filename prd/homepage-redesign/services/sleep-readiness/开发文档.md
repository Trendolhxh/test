# 入睡准备度计算服务 · 开发文档

> 本文档定义入睡准备度服务的**产品需求**——做什么、何时触发、输出什么、异常时走哪条降级路径。
>
> **MVP 计算逻辑**（3 因子平均 · 研发可直接实现）→ [算法-MVP.md](./算法-MVP.md)

---

## 1. 功能边界

### 1.1 做什么

- 在 hero 夜间模式激活期间，产出「入睡准备度」百分比（`0–100`）与 4 档分档文字，供 hero 渲染
- 夜间模式内周期刷新（传感器数据变化会影响结果）
- 预留「环境准备度」子分供未来夜间详情页消费，v1 不在 hero 展示

### 1.2 不做

| 不做 | 归谁 |
|---|---|
| 高能时长 / 节律时段计算 | 高能时长计算服务 |
| 推荐入睡时间 | `prd/sleep-window/` |
| 行动建议 | Agent 对话模块 |
| UI 文案 / 分档颜色 | `hero` 模块 |

### 1.3 协同关系

- **hero** 是 v1 唯一消费方；进入夜间模式时触发首次请求、退出时停止刷新
- **event-pipeline** 提供当日事件（午睡 / 运动）作为睡眠压力子分的输入上下文
- **sleep-window** 决定 hero 何时进入夜间模式；本服务不直接消费其契约

---

## 2. 计算模型

### 2.1 MVP 版本（当前）

MVP 简化为 **3 因子等权平均**：清醒时长、心率相对静息心率的 delta、HRV 相对基线的 delta。完整公式见 [算法-MVP.md](./算法-MVP.md)。

v1 hero 展示的 `readiness_value` 即 MVP 算法输出；`env_readiness_value` 返回 `null`（Environment 轴非 MVP 范围）。

### 2.2 完整版本（v2+ 升级路径）

MVP 跑通后可升级为两轴模型：

| 子分 | 回答什么 | 升级后消费方 |
|---|---|---|
| **Body Readiness** | 身体此刻距离入睡状态有多远（三子分乘法核：睡眠压力 × 节律就绪 × 唤醒抑制） | hero 主数字 + 分档 |
| **Environment Readiness** | 卧室物理条件是否支持入睡（温 / 光 / 噪 / CO₂ 加权） | 夜间详情页 |

两轴不合并为单一总分。

---

## 3. 触发与生命周期

| 事件 | 动作 |
|---|---|
| hero 进入夜间模式（自动或手动） | 立即发起首次计算 |
| 夜间模式激活期间 | 周期刷新（间隔由算法侧确定） |
| 检测到用户入睡（`night_sleep.state = in_progress`） | 停止刷新 |
| hero 退出夜间模式 | 停止刷新 |

日间模式 / Tab 切走 / 后台唤回（非冷启动）时，本服务不运行。

---

## 4. 输出契约

hero 直接渲染本服务输出，不做二次判定。

| 字段 | 含义 |
|---|---|
| `readiness_value` | Body Readiness 整数百分比（0–100） |
| `bucket` | 4 档分档文字（见下表） |
| `env_readiness_value` | Environment Readiness 整数百分比；传感器整体不可用时为 `null` |
| `status` | `ready` / `computing` / `failed`——决定 hero 走正常态还是异常态 |

### 4.1 分档文字

| 档位 | 文字 | 语义 |
|---|---|---|
| 1 | `身体仍活跃` | 生理唤醒度高，尚未进入放松 |
| 2 | `正在放松` | 开始向睡眠方向转变，尚未到位 |
| 3 | `已进入放松` | 生理信号接近入睡前理想区间 |
| 4 | `身体急需休息` | 过度疲劳（非单调排序，见下方说明） |

> 「身体急需休息」与「已进入放松」不是分数越高越好的单调排序——前者代表过度疲劳状态。具体百分比区间由算法侧与 hero UI PRD §6.3 共同定稿（单一真相源在本服务）。

## 5. 异常 → 降级

| 异常 | hero 表现 |
|---|---|
| 关键生理信号（HRV 等）采集失败但其他信号可用 | 正常展示，精度下降，不向用户提示 |
| 环境传感器整体不可用 | `env_readiness_value = null`；Body 分正常展示 |
| HealthKit 未授权 | hero 走「空数据」态：`Apple Health 数据未更新` |
| 计算超时 / 返回字段不完整 | hero 走「同步失败」态：`数据同步失败 · 点击重试` |
| 周期刷新单次失败 | 静默跳过，保持上次结果；连续多次失败后走「同步失败」态 |
| 新用户无个人基线 | 使用群体先验，不降级为「不可用」；不向用户展示"基线建立中"提示 |

## 6. 未决项

### 待 MVP 上线后验证

- [ ] **bucket 4 档百分比区间**：MVP 首版在 [算法-MVP §6](./算法-MVP.md) 预估；实际数据上看分布后调整
- [ ] **3 因子阈值**：清醒时长 12h 上限 / HR delta 20bpm / HRV delta 20ms 是否合理
- [ ] **冷启动群体先验**：`HR_rest = 60bpm` / `HRV_baseline = 40ms` 是否合适
- [ ] **MVP 体感准确度**：若 MVP 3 因子不足以区分用户真实入睡状态，升级到完整两轴模型

### 待算法侧

- [ ] 周期刷新的具体间隔
- [ ] 设备佩戴质量门限（信号质量不达标时如何剔除输入）
