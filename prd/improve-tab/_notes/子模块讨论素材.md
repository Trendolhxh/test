## L3.1 首屏结构（hero 模块素材）

**四段并列，自上而下：**

| 节 | 名称 | 承担 | 视觉权重 |
|---|---|---|---|
| §1 | 目标 | 用户此刻为什么来（提神 / 助眠入睡） | 大 · 可点切换 |
| §2 | 你当前的情况 | 多维度诊断并列（1-3 条） | 中 · 文字陈述 |
| §3 | 解法树 | 主位大卡 + 次位小卡 · 1:1 映射 §2 | 大 · 主位唯一 CTA |
| §4 | 路径延展 | 为什么 / 今晚还能怎样 / 长期改善 | 小 · 延展位 |

**§1 目标 · 第一版只做两个**：`提神` 与 `助眠入睡`。默认值由时段决定（`now ≥ 推荐入睡时间 - 3h` 切换到夜间目标；复用 Homepage 的切换规则）。用户手动切换则整屏刷新。更多目标（如 `午后醒脑` / `心累放空`）留待 v2。

**§2 诊断 · 并列 1-3 条**：每条 = 一句陈述 + 一个方法体系 tag（如 "睡眠节律紊乱 · 生理节律"）。不排优先级、不给分数、不标"主要原因"。并列体现"鉴别诊断"而非单点锁定。

**§3 解法树 · 1:1 映射 §2**：§2 几条诊断，§3 就几张卡。主位卡唯一（引擎推的"此刻最先做的"），有 CTA；其他为次位小卡，可见可点但无 CTA 突出。卡片右上角带 `更多 ↗` 入口。

**§4 延展位 · 3 种类型**：
- `为什么会这样` · 科普阅读（承接 §2 诊断）
- `今晚 / 今日还能怎样` · 行动延伸（承接 §3 主位消费完的下一步）
- `长期改善` · 习惯养成（承接当前目标的长期方案）

**硬约束**：四节全部首屏可见。§1 §2 §3 之间禁止折叠。§4 允许滚动到达，但不置于任何折叠层之下。

## L3.2 首屏交互（hero 模块素材）

**核心规则**：目标切换 = 整屏刷新；节点消费返回 = 局部更新。两者严格区分。

**目标切换节奏**（整屏刷新）：

1. 用户点 §1 目标 → 弹出 sheet 选择（`提神` / `助眠入睡`）
2. 选定 → 300ms fade-out 整屏
3. 1-2s loading（一句人话，不转圈）
4. 400ms fade-in 新内容
5. 总计 1.2-1.4s

**Loading 文案硬约束**：
- 必须是人话（如 "正在重新看一眼你的状态"），禁止 "加载中 / Loading..."
- 不给进度条、不给百分比
- 超过 2s 则换第二句（避免停滞感），但不解释是什么在慢

**为什么要整屏刷新**：三段论的结构前提（目标）变了，诊断与解法全部需要重算。部分刷新会让用户误以为"诊断还是原来的诊断"，破坏逻辑可见性。

**节点消费返回 · 局部更新（案 B · L5 已裁定）**：主位卡状态变"已完成"，次位依降权规则升主位，§4 延展更新，其余不动。为什么不整屏刷新：目标没变，重画首屏等于"否认你刚才做过的事"。

## L3.3 页面性格与气质（hero 模块素材 + 全 Tab 气质基线）

**定位句**：**一位读过睡眠医学、愿意晚上 11 点接你电话的朋友。**

不是 Calm（疗愈品牌）、不是 Oura（数据报表）、不是大模型对话框（通用问答）。是"你信赖的那个人"在这个时刻告诉你怎么办。

**性格双向轴**（对齐 Apple HIG · Clarity / Deference / Depth）：

| 维度 | 位置 | 含义 |
|---|---|---|
| 冷静 ↔ 活泼 | 强偏冷静 | 不用感叹号 / emoji / 鼓励式话语 |
| 克制 ↔ 丰富 | 偏克制 | 视觉密度低，一屏只讲一条主路径 |
| 陈述 ↔ 叙事 | 居中 | 诊断陈述式，解法卡摘要可带一句引导 |
| 静态 ↔ 动态 | 偏静态 | 无自动轮播 / 视差 / 呼吸灯 |
| 专家 ↔ 朋友 | 强偏朋友 | 临床术语可出现，但必须被翻译 |

**对标反例**：

| 反例 | 它是什么 | 改善 Tab 刻意回避 |
|---|---|---|
| Calm / Headspace | 内容货架 | 不做通用类目陈列 |
| Oura / Whoop 报告页 | 昨晚评分 + 历史图表 | 不做数据报表 / 不出图表 |
| 大模型对话框 | 光标等你打字 | 不做首屏通用问答 |
| 小红书健康内容 | 算法流 + 点赞收藏 | 不做流式推荐 / 热度排序 |
| 三甲医院患教小程序 | 条文式医嘱 | 不做"请遵循以下 5 条" |

**视觉基调**：低光纸面（夜间模式 first），背景随时段渐变（日间偏暖纸、夜间偏冷藏青），同 Homepage Hero 气场。首屏禁止出现心率 / HRV / 睡眠阶段图表 —— 那是 Homepage 的语言，在这里会破坏"行动"心智。

**声音基调**：真人录音为主，温厚中性（非 ASMR 耳语、非广播腔、非电子 TTS）。无默认 bgm；用户自选 bgm 留待 v2。

**一句话自证**：如果把这一屏截图发给一位读过睡眠医学的朋友，她不会觉得"你们也太业余了"；发给普通用户，不会觉得"这是给医生看的"。两头都过，才算气质对了。

## L3.4 节点消费完成态（content-consumption 模块素材）

**节点 = §3 解法卡的 CTA 所承接的那一段 3-15 分钟可做 / 可听 / 可读内容**。消费完成态按内容类型分叉，两套尾屏不通用。

**知识性内容尾屏**（科普阅读 / 方法讲解 / 原理类）：

| 按钮 | 语义 | 下一步 |
|---|---|---|
| `明白了` | 确认闭环 | 返回首屏 · 计入"已消费此条" |
| `没明白 · 问一下` | 追问 | 进入 Agent 追问对话 · 承接已消费内容上下文 |

**音频类内容尾屏**（放松训练 / 呼吸引导 / 睡前故事 / 冥想类）：

| 按钮 | 语义 | 下一步 |
|---|---|---|
| `收藏` | 正反馈 · 升权 | 记入偏好库 · 未来此主题升权但非必现 |
| `再听一次` | 当次继续 | 重播同一段音频 |
| `换一段` | 当次否定 | 同机制同目标下换一条音频 · 并对该条长期降权 |

**为什么分叉**：知识性内容单次消费即完成认知闭环（"明白了"是自然终点）；音频类是反复消费品（"好的那段我晚晚都想听"），必须支持重复使用与个性化偏好积累。用同一套按钮会让两种内容的反馈信号互相污染。

**iOS 手势返回**：不禁用，但语义等同于"直接关闭"，不计入"已消费"（L5.3 消失测试已裁定）。

**不做的完成态**：
- **评分**（1-5 星 / 有帮助 vs 没帮助）—— 让用户替 App 做判断，与权力分配矛盾；评分数据噪声大
- **分享**（到社交平台 / 生成卡片）—— 改善 Tab 是私人场景，分享破坏"不被看见"的信任感
- **打卡 / 连续天数 / 徽章** —— 游戏化与临床严谨冲突，且绑架用户

## L3.5 首屏动态更新规则（path-engine 模块素材）

**§2 §3 §4 由三源组装实时生成**：

| 源 | 含义 | 来自 |
|---|---|---|
| 当前场景 | 此刻状态 + 选定目标 + 时段 | Homepage 状态摘要 · `profile-engine` · §1 |
| 历史消费 | 近 7-30 天消费过的节点 / 机制 / 主题 | App 内埋点 |
| 偏好库 | 收藏 / 换一段 / 隐式偏好（完成率 · 再听率） | 节点完成态累积 |

**组装逻辑由 `path-engine` 承担**。首屏每次可见时都应重新组装，不缓存上一次结果超过 15 分钟。

**降权规则**（防止"总是同一张卡"）：

| 事件 | 对该条 / 该机制的权重影响 | 时长 |
|---|---|---|
| 节点消费完 + `明白了` | 该条降权 | 短期 7 天不重推 |
| 节点消费完 + `收藏` | 该条升权（但非必现） | 长期 · 偏好库 |
| 节点消费完 + `换一段` | 该条长期降权 | 长期 · 偏好库（显式拒绝信号） |
| 节点消费完 + `再听一次` | 该条略升权 | 短期 |
| 首屏刷新但用户未消费任何节点 | 上次主位降权 | 当次 |

**为什么收藏"非必现"**：如果收藏 = 必出现，收藏夹就退化成用户的"今日必做清单"，把判断权又推回用户（矛盾于权力分配）。收藏是给 `path-engine` 的偏好信号，不是给用户的置顶锁定。

**为什么"换一段"是长期降权而非永久屏蔽**：用户可能当下心境不想听，不代表永远不适合。屏蔽是重决策，不该由一次轻点完成。

**节点消费后首屏局部更新规则（案 B）**：主位卡 → 已完成标识 · 次位 → 依降权升主位 · §4 延展更新 · 其余静置。

**硬约束**：
- 首屏禁止出现"今日精选" / "编辑推荐" / "热门" —— 这些是内容库的货架语言
- 两次刷新之间，三源都没变时允许返回相同组装结果；但不得缓存超过 15 分钟
- 降权规则的具体窗口（7 天 / 短期 / 长期）由 `path-engine` 实现决定，PRD 只约束方向与相对关系

## L3.6 「查看更多」入口（topic-detail 模块素材）

**位置**：每张解法卡（主位 + 次位）右上角 `更多 ↗`。

**指向**：该卡所属主题的深度页（二级下钻 · `topic-detail` 模块）。深度页承载同机制 / 同方法体系下的更多节点（如主位是"CBTI · 刺激控制", 深度页展示 CBTI 相关的其他节点 · 睡前认知重评 / 睡眠限制 / 夜间觉醒处理等）。

**为什么给每张卡各自的 `更多 ↗`，而不是首屏底部放一个全局"浏览所有内容"**：
- 全局浏览入口 = 内容库路线。用户一旦进入全局浏览，就开始替 App 做判断。
- 每张卡的 `更多 ↗` 是"顺着这条路径继续走"，仍在路径语境内；即使用户挑选，挑的也是同一主题的同一方法体系下的节点，不是跨主题自由探索。

**深度页不是内容库**：深度页是路径的"加深"，不是"陈列"。页面内容仍由 `path-engine` 组装（同主题下的优先级、历史消费降权同样生效），不是静态目录。

**硬约束**：
- 禁止在首屏或其他位置放"浏览所有内容" / "内容库" / 按类目筛选的入口
- `更多 ↗` 的指向必须是同主题同方法体系，不跨机制跳转（如不能从"CBTI · 刺激控制"的 `更多 ↗` 跳到"冥想"）

## L3.7 Agent 登场点（agent-followup 模块素材）

**Agent 仅在节点消费后承接已有上下文的对话**。首屏、解法卡、延展位、深度页都**不放** Agent 入口。

**两个触发点**：

| 触发按钮 | 位置 | 承接上下文 |
|---|---|---|
| `没明白 · 问一下` | 知识性内容尾屏 | 已消费内容全文 + 当前目标 + 画像 + §2 诊断 |
| `告诉我感觉` | 音频类内容尾屏（可选 · 非必现）| 已消费音频摘要 + 当前目标 + 画像 |

**窄问题策略**：Agent 只回答"关于刚才这段内容 / 这个机制 / 你当下感觉"的问题。不做通用睡眠问答、不做闲聊、不做泛健康咨询。窄问题 + 上下文丰富度（内容全文 + 画像 + 当前状态）共同弥补 Agent 算法本身的不稳定。

**为什么首屏不放 Agent 入口**：
- 首屏是"App 代你判断"的主位。在这里放 Agent 等于"你自己问吧"，权力分配瞬间反转（矛盾于跨 Tab 一致性）。
- 首屏的 Agent 入口会让用户绕过三段论直接提问，三段论的信任闭环失效。
- 大模型在无上下文时的回答质量极不稳定；iSho 的壁垒正是"Homepage + 画像 + 消费历史"的上下文沉淀，在首屏提问等于丢掉壁垒。

**硬约束**：
- Agent 入口只能出现在内容尾屏，禁止在首屏 / 卡片列表 / 深度页 / 任何一级位置
- Agent 回答出错或偏离窄问题时，必须有 fallback 回到"让我帮你回到当前路径"，不允许跑偏成通用对话
- 对话记录不回灌到首屏"历史消费"降权（对话不等于节点消费）

## L3.8 五条硬约束 · 完整 Do / Don't（hero 模块素材 · 实施期名词审计清单）

### 1 · 逻辑可见

| Do | Don't |
|---|---|
| §1 §2 §3 §4 全部首屏可见 | §2 诊断折叠 · 点开看 |
| 每张解法卡露方法体系 tag | 只露"建议你做 X"不说凭什么 |
| 目标切换整屏刷新，让诊断与解法一起变 | 切目标只换文案，诊断保留旧值 |

### 2 · 动态组织

| Do | Don't |
|---|---|
| §2 §3 §4 由 `path-engine` 三源组装 | 预制话术库轮播 / 固定 24 套诊断 |
| 同场景多次进入允许返回不同主位 | 首屏固化"今日精选" / "编辑推荐" |
| 降权规则让不同天看到不同主位 | 同一主位连续出现 7+ 天 |

### 3 · 主位 CTA 唯一

| Do | Don't |
|---|---|
| §3 主位一张大卡 · 一个 CTA | 多 CTA 并列让用户挑 |
| 次位小卡可见可点，但无 CTA 突出 | 次位也带 CTA · 与主位视觉平权 |
| CTA 文案是行动（`听 8 分钟 · 呼吸引导`）| CTA 是分类（`冥想` / `音频`）|

### 4 · 临床源头明示

| Do | Don't |
|---|---|
| 每张解法卡标方法体系（CBTI / 放松训练 / 睡眠卫生 / 生理节律）| 只说"专家推荐" / "医学建议" |
| 术语必有一句人话翻译（"刺激控制 —— 让床只跟睡觉挂钩"）| 裸露 CBTI / sleep restriction / CBT-I 英文缩写 |
| §2 诊断带方法体系 tag · §3 解法带方法体系 tag | 没有任何临床锚定 · 让内容看起来像"编辑的建议" |

### 5 · 诊断 1:1 映射解法

| Do | Don't |
|---|---|
| §2 几条诊断 · §3 就几张卡 · 数量严格对齐 | §2 三条诊断 · §3 五张卡（多出来的卡无所依据）|
| §3 卡面包含"针对你 §2 的哪条诊断"这句锚定 | §3 只写解法方法 · 不回指 §2 |
| 某条诊断在当前场景不适用，§3 对应卡隐藏而非替换 | §3 有卡但 §2 没有对应诊断 |

## L4.1 文案与语言 Do/Don't（shared/文案.md 素材）

| Do | Don't |
|---|---|
| §2 诊断用陈述句（"你清醒已 9h，超过自然上限 2h"）| 感叹句 / 反问 / 鼓励式（"加油，你可以的！"）|
| 临床术语必带一句人话翻译 | 裸 CBTI / sleep restriction / circadian phase delay 等英文缩写 |
| 用户原话复述开头（"累爆了 / 睡不着"）| 产品术语开头（"进入改善路径" / "开始诊断"）|
| 解法 CTA 是行动 + 时长（"听 8 分钟 · 呼吸引导"）| CTA 是分类（"冥想" / "音频"）|
| Loading 是人话（"正在重新看一眼你的状态"）| "加载中" / "Loading" / "..." |
| 数字承诺留余地（"通常 7-15 分钟见效"）| "99% 有效" / "立刻改善" / "保证入睡" |
| 第二人称（"你"）| 第三人称（"用户" / "朋友"）/ 第一人称冒认（"我们建议"）|

## L4.2 内容与临床安全 Do/Don't（content-consumption 模块素材 + 独立临床安全 PRD 待立项）

| Do | Don't |
|---|---|
| 每张解法卡标方法体系源头（CBTI / 放松训练 / 睡眠卫生 / 生理节律 ...）| 只写"专家推荐" / "医学建议"无出处 |
| 涉及药物 / 医嘱类内容带"请咨询医生"明出口 | 药物剂量 / 用药顺序 / 处方替代建议 |
| 急性风险（连续严重失眠多日 / 情绪极低 / 自伤意念）→ 标准化导出口（走独立 PRD）| 改善 Tab 内尝试"心理咨询"角色接住 |
| 每张卡严格服务于 §1 当前目标 | 提神目标下出现"助眠"内容 / 反之（跨目标串内容）|

## L5 消失测试 · 完整论证（已裁定）

### 1 · 静态"当前诊断"文本 vs 首屏 Agent 对话入口

**结论：删首屏 Agent 对话入口。保留静态诊断文本。**

- 表面上两者都在回答"我现在是什么状态"。
- 静态诊断是 §2 三段论的支柱（逻辑可见 · 硬约束 1），承担"让用户看懂为什么"。
- 首屏 Agent 会让用户绕过三段论直接提问，三段论信任闭环失效。
- Agent 在无上下文时回答质量极不稳定，丢掉 iSho 相对通用对话 AI 的结构性壁垒。
- **只剩静态诊断 · App 不塌；只剩首屏 Agent · App 塌。**

### 2 · 解法卡次位列表 vs `更多 ↗` 主题深度页

**结论：两者不真重叠。保留双方。**

- 次位卡承担 §3 "1:1 映射 §2 诊断"的结构显现；删之 §3 退化为单点，三段论崩。
- `更多 ↗` 承担"同主题同方法体系的更多节点"；删之 App 变浅，但三段论仍完整。
- 两者服务不同用户需求（看全 vs 往深），不构成消失测试的有效对。
- 优先级：次位卡 = v1 必出；`更多 ↗` = v1 推荐出（若 v1 深度页内容储备不足可推迟至 v2，但首屏结构不变）。

### 3 · 内容尾屏 `明白了` 按钮 vs 直接关闭返回

**结论：保留 `明白了` / `没明白 · 问一下` 作为显式完成信号。"直接关闭"仍可用，但不计完成。**

- 两者都能退出阅读页，看似冗余。
- 但"直接关闭"是无信号返回 —— App 无法区分"看完了"和"没看进去"，降权规则失去输入。
- `明白了` / `没明白 · 问一下` 是显式完成信号，二选一，信号清晰。
- iOS 系统手势返回不禁用，但路径语义上等同于"直接关闭"，不计入"已消费"。
- **信号锁定在显式按钮上 · App 不塌；信号只靠关闭推测 · App 塌（偏好库变噪声）。**

### 4 · 节点完成后首屏变化 · A 完全不动 / B 局部升级 / C 整屏重组

**结论：选 B 局部升级。A、C 均砍。**

- **A · 完全不动**：用户消费完回到首屏发现主位卡还在原位，误以为"这事没被记住"。违反"已消费"的即时反馈期望。App 塌。
- **B · 局部升级**：主位卡变"已完成"标识 · 次位依降权升主位 · §4 延展更新 · 其余静置。符合"目标没变则根没变 · 枝末变"的逻辑一致性。**选此案。**
- **C · 整屏重组**：刚消费的内容与主位被清空重画，破坏消费的"结束感"；让用户误以为"之前那一套已作废"。App 塌。

## L6 场景映射 · 完整示例（hero + path-engine + 内容团队素材）

两个首发场景下 §1-§4 的具体答案示例。本表是"可执行样本"，内容团队据此理解"一条完整改善路径长什么样"。实际 `path-engine` 输出会根据画像 / 历史消费 / 偏好动态变化，下表示例取"中性画像 + 首次使用"的基础组装。

### 场景 1 · 日间即时不适 · "我累爆了怎么办"

| 节 | 内容 |
|---|---|
| §1 目标 | 提神 |
| §2 当前（3 条）| ① 过去 6h 无有效恢复 · `生理节律`<br>② 清醒已 9h 超自然上限 · `睡眠卫生`<br>③ 昨晚深睡不足 · `CBTI·睡眠质量` |
| §3 主位（CTA）| 15 分钟 microsleep + 醒后光暴露 · `CBTI·日间恢复`（CTA：`跟着做 15 分钟`）|
| §3 次位（无 CTA）| ① 5 分钟呼吸激活 · `放松训练·逆向激活`<br>② 10 分钟户外步行曝光阳光 · `生理节律` |
| §4 延展 | ① 为什么是 15 分钟 · 更长反而更昏沉（科普）<br>② 下一段高能时段预估（跳 Homepage）<br>③ 长期改善 · 把上床时间稳定在 23:30 前 |

### 场景 2 · 睡前即时不适 · "我睡不着怎么办"

| 节 | 内容 |
|---|---|
| §1 目标 | 助眠入睡 |
| §2 当前（3 条）| ① 认知过度唤醒（反刍思维）· `CBTI·认知重评`<br>② 体温曲线偏高 · `生理节律`<br>③ 睡前蓝光暴露过量 · `睡眠卫生` |
| §3 主位（CTA）| 8 分钟"把脑袋关进抽屉"认知重评引导 · `CBTI·认知重评`（CTA：`听 8 分钟`）|
| §3 次位（无 CTA）| ① 10 分钟温水足浴指引 · `生理节律`<br>② 屏幕切夜间模式 · `睡眠卫生` |
| §4 延展 | ① 为什么认知重评对入睡有效（科普）<br>② 今晚还能做什么（行动延伸）<br>③ 长期改善 · 把起床时间稳定锁在 7:30 |

### 场景映射硬约束

- §2 条数 = §3 卡数（硬约束 5）。示例均 3/3。
- §3 主位唯一且带 CTA（硬约束 3）。
- §2 §3 每条带方法体系 tag（硬约束 4）。
- 两场景的 §3 内容**严格不交叉**：提神场景不出现助眠内容 · 反之亦然（L4.2）。
- §4 三条延展对应"为什么 / 今晚 / 长期"三种消费姿态。

### 场景映射取舍

1. **为什么首发只 2 个场景** —— 即时不适是用户原话最高频场景；其余（长期 / 科普 / 今日行动）是消费完的自然延展，不作独立入口。
2. **为什么示例用"中性画像"而非极端画像** —— PRD 样本示范"常规响应"，不是"极限测试"。极端画像（如连续 10 天严重失眠）由急性风险导出口承接。
3. **为什么 §2 都给 3 条而非 1-2 条** —— 1 条退化成单点诊断；2 条存在"主副"潜意识排序；3 条是多维诊断的最小充分展示。`path-engine` 实际可 1-3 条动态调整，PRD 示例取上限。
4. **为什么主位都是 CBTI 方法体系** —— v1 主位优先给临床背书最强的方法。次位给生理节律 / 放松训练 / 睡眠卫生做维度补充。不是"CBTI 万能"，是"首发主位优先证据等级"。
