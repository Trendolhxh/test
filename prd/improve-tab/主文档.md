# 改善 Tab 主 PRD

> iSho 第二个 Tab 的指导方针级 PRD。按 Apple 设计方法论 7 层收敛漏斗组织。
> 每一层给出**结论**与**取舍逻辑链路**。只讲核心信息与原则，细节下沉至 [`_notes/子模块讨论素材.md`](_notes/子模块讨论素材.md) 供拆子模块时认领。
> 状态：v1.1（2026-04-23）— 轻量版 · L1-L8 完稿 · 阶段 1 收口。

---

## L1 · 问题定位

### 一句话产品定位

> **iSho 的第二个 Tab。"我累了 / 我睡不着"时不给孤立建议、也不给内容库让你自己挑——给你一条可信的改善路径：选定目标 → 解释当前 → 多维度解法 → 此刻可做 / 可听 / 可读的内容节点。把 CBTI 等临床方法论消费电子化。**

### 用户原话与场景

| 场景 | 频率 | 用户原话 | 用户真实问题 |
|---|---|---|---|
| 日间即时不适 | 高频 | "我累爆了怎么办" | 现在就要改善 + 要知道怎么做 |
| 睡前即时不适 | 高频 | "我睡不着怎么办" | 今晚想好睡 + 要一套方法 |

**延展场景**（不作为独立入口，是即时不适消费完后的自然延展）：

- 为什么我会这样 · C 科普阅读
- 今晚 / 今日还能怎样 · B 行动延伸
- 长期改善路径 · D 习惯养成

### iSho 两个 Tab 的心智对子

| 场景 | 用户原话 | 承接 Tab | 答案形态 | 消费深度 |
|---|---|---|---|---|
| 晨起 | "今天能不能打仗" | Homepage | 高能时长数字 + 分档 | 轻（~30s） |
| 日间自觉下滑 | "我是不是真到点了" | Homepage | 当前时段对照 | 轻（~30s） |
| 日间即时不适 | "我累爆了怎么办" | 改善 Tab | 改善路径（目标 - 当前 - 解法） | 中（3-15 min） |
| 睡前即时不适 | "我睡不着" | 改善 Tab | 改善路径（目标 - 当前 - 解法） | 中（3-15 min） |

**Homepage = 诊断 · 轻消费 · 数据可视化；改善 Tab = 行动 · 中消费 · 内容节点。两个 Tab 消费深度分工明确。**

### 取舍逻辑链路

1. **场景聚焦"即时不适"** —— 用户对"睡眠 / 精力改善"的诉求形态多样（即时缓解 / 今日行动 / 长期习惯 / 认知科普），但用户原话最多的始终是"我现在 X"的即时诉求。其余三类是即时诉求阅读完后的自然延展（B/C/D），不作为独立入口。
2. **此 Tab 天然回避与大模型竞争** —— 即时不适场景下，用户不会打一段字描述状态给大模型再等回答。iSho 的 Homepage 已经知道用户当前状态，用户不需要重述。这是 iSho 相对通用对话 AI 的**结构性壁垒**。
3. **"App 代你判断"权力分配 · 跨 Tab 一致** —— Homepage 已确立此权力分配（诊断权在 App）。改善 Tab 继承（行动推荐权在 App）。同一产品的两个 Tab 必须共享权力分配，否则用户会精神分裂。
4. **不和 Calm / Headspace 正面竞争** —— 它们按通用类目陈列内容货架，用户自己找"我现在需要什么"；改善 Tab 基于（当下状态 × 目标 × 画像 × 历史消费 × 偏好）动态组织路径，**给你一个**而不是**给你一排**。

## L2 · 核心对象「改善路径」

### 一句话定义（onboarding 级）

> **「改善路径」—— 从你选定的目标（提神 / 助眠入睡）出发，经过引擎对你当前状态的多维度诊断，给出对应的解法卡，每张卡承载一段 3-15 分钟可做 / 可听 / 可读的内容节点。每条路径根据你、场景、历史消费、偏好动态组织。**

### 心智模型

| 维度 | 采用 | 砍掉 |
|---|---|---|
| 核心对象 | 改善路径（目标 - 当前 - 解法三段论 · 树状） | 单点建议 / 内容分类库 / 视频列表 |
| 组织方式 | 动态生成（目标 × 画像 × 状态 × 历史消费 × 偏好） | 预制决策树 / 话术库 / 固定分类 |
| 主位节点 | 引擎推的"此刻最先做的"（唯一 CTA） | 多 CTA 并列 / 让用户自己挑 |
| 分支展示 | 次位卡可见可点（体现树状） | 只露主位 / 折叠起来 |
| 信任来源 | 逻辑透明（目标 · 诊断 · 解法都摊开）+ 临床背书（方法体系明示） | 评分 / 热度 / 推荐榜 |
| 权力分配 | App 选逻辑，用户走逻辑 | 用户挑内容 |
| 内容价值 | 逻辑骨架上的节点 | 可独立消费的 SKU |
| 消费深度 | 中消费（3-15 min）为主，重消费辅 | 轻消费（Homepage 已覆盖） |

### 三段论 · 医生工作流的消费级化身

改善路径的结构与医生工作流**同构**，这不是巧合，是刻意的：

| 医生工作流 | 改善 Tab 结构 |
|---|---|
| 主诉 | §1 用户选定的目标（提神 / 助眠入睡） |
| 鉴别诊断（多维度） | §2「你当前的情况」多诊断并列 |
| 处方（对应诊断） | §3 解法卡（1:1 对应诊断） |
| 推荐优先项 | 主位卡有 CTA · 其他次位卡无 CTA 突出 |
| 追问 / 随访 | 节点消费完的「没明白」Agent 追问 / 「收藏」偏好记录 |

这是 "CBTI 消费电子化" 的结构体现 —— 不是把 CBTI 简化，是把 CBTI 的推理链条用消费级的 UI 呈现。临床的严谨藏在结构里，用户看到的是干净的三段落。

### 取舍逻辑链路

1. **改善路径 vs 单点建议** —— 健康场景中孤立建议（"去深呼吸"）无法承担信任：用户不知道为什么、凭什么、对不对。目标 - 诊断 - 解法三段论让用户"看懂就信了"。信任靠**逻辑可见**，不靠品牌或权威。
2. **改善路径 vs 内容库** —— 内容库把判断权让给用户（自己挑），与 Homepage 的"App 代你判断"权力分配**矛盾**。同一产品两个 Tab 必须一致，否则用户精神分裂。
3. **树状而非单线** —— 临床逻辑本来就是分支结构（CBTI / 正念 / 生理节律 / 睡眠卫生 各自服务不同机制）。UI 压成单线会抹掉产品的专业感。多维诊断 × 多张解法卡 1:1 映射，树状自然浮现，用户不需要被教育"这是树"。
4. **动态组织 vs 预制话术库** —— 方法体系多元，(目标 × 画像 × 状态 × 历史消费 × 偏好) 的组合无法穷举。系统必须具备"由多维输入组装一条路径"的能力 —— 这是 `path-engine` 模块的存在理由。
5. **消费电子化的真正含义** —— 不是简化 CBTI（那会失效），而是把临床严谨嵌入消费级的语言 + 交互。像 Apple Watch 的 ECG —— FDA 级精度 + 普通人能按的一根表冠。改善 Tab 是 CBTI 的类似化身。
6. **为什么内容代表产品调性** —— 逻辑链只是骨架，每个节点的文字 / 音频 / 练习是产品的"音色"。粗糙节点让再好的逻辑失效。内容生产流程（文献 → AI 提炼 → 人工精选 + 真人录音）是调性源头，写入 L3 气质章节约束。

## L3 · 首屏结构与气质（骨架）

> 首屏是改善 Tab 的主位。"改善路径"的三段论必须在首屏被完整看见。本节只给骨架与原则；详细 Do/Don't、交互节奏、气质轴、完成态、降权规则、Agent 策略已下沉至 [`_notes/子模块讨论素材.md`](_notes/子模块讨论素材.md)，供拆子模块时使用。

### 首屏四节

| 节 | 名称 | 承担 |
|---|---|---|
| §1 | 目标 | 用户此刻为什么来（v1 只做 `提神` / `助眠入睡`） |
| §2 | 你当前的情况 | 多维度诊断并列（1-3 条 · 每条带方法体系 tag） |
| §3 | 解法树 | 主位大卡 + 次位小卡 · **1:1 映射 §2** · 主位唯一 CTA |
| §4 | 路径延展 | 为什么 / 今晚还能怎样 / 长期改善 |

### 五条硬约束

首屏级硬约束。违反任一条即 PRD 对齐失败。每条的完整 Do/Don't 见 `_notes` L3.8 章。

1. **逻辑可见** · §1-§4 首屏全露 · 禁折叠 · 每张卡露方法体系出处
2. **动态组织** · `path-engine` 三源组装（当前场景 / 历史消费 / 偏好库）· 禁话术库轮播
3. **主位 CTA 唯一** · §3 主位一张 · 次位可见可点但无 CTA 突出
4. **临床源头明示** · 每卡标方法体系（CBTI / 放松训练 / 睡眠卫生 / 生理节律 ...）· 术语必翻译
5. **诊断 1:1 映射解法** · §2 几条 · §3 就几张 · 数量严格对齐

### 页面气质

**定位句**：**一位读过睡眠医学、愿意晚上 11 点接你电话的朋友。**

不是 Calm（内容货架）、不是 Oura（数据报表）、不是大模型对话框（通用问答）。视觉低光纸面、声音真人录音、语气冷静克制。详见 `_notes` L3.3 章的完整气质轴与对标反例表。

### 关键交互

- **目标切换 = 整屏刷新**（1.2-1.4s · 带人话 loading 文案）：根变则枝必变
- **节点消费返回 = 局部更新**（案 B · L5 已裁定）：主位变已完成 · 次位升主位 · §4 延展更新

### 核心取舍

1. **四节首屏全露 vs 折叠** —— 藏任何一节都让其余节变成"单点建议"，三段论信任闭环靠全露维持。
2. **目标切换整屏刷新 vs 部分刷新** —— 目标是三段论的根，部分刷新会让用户误以为"诊断还是原来的"，破坏硬约束 1。
3. **真人录音 vs 生成式音频** —— 温厚中性的气质约束与当前 TTS 识别性冲突；真人录音是成本最高但唯一不破坏气质的选项。

## L5 · 消失测试结论

四组候选对的选边结论。完整论证与连带修订见 [`_notes/子模块讨论素材.md`](_notes/子模块讨论素材.md) L5 章。

| # | 候选对 | 结论 | 一句话理由 |
|---|---|---|---|
| 1 | 静态"当前诊断" vs 首屏 Agent 入口 | **删首屏 Agent** | 首屏 Agent 会架空三段论 + 丢掉 iSho 上下文壁垒 |
| 2 | 解法卡次位列表 vs `更多 ↗` 深度页 | **两者不重叠 · 保留双方** | 前者是 §3 树状结构 · 后者是同主题加深，服务不同需求 |
| 3 | 内容尾屏 `明白了` vs 直接关闭 | **保留显式按钮为完成信号** · iOS 手势返回不计完成 | 只靠关闭推测会让偏好库变噪声 |
| 4 | 节点完成后首屏 A 不动 / B 局部升级 / C 整屏重组 | **选 B 局部升级** | A 让"事没被记住" · C 否认刚消费的内容 · 两端都塌 |

v1 两个首发场景。完整的 §1-§4 示例（§2 诊断 / §3 解法主位与次位 / §4 延展的具体内容）已下沉至 [`_notes/子模块讨论素材.md`](_notes/子模块讨论素材.md) L6 章，供 `hero` + `path-engine` + 内容团队拆模块时使用。

| 场景 | 频率 | 用户原话 | §1 目标 |
|---|---|---|---|
| 日间即时不适 | 高频 | "我累爆了怎么办" | 提神 |
| 睡前即时不适 | 高频 | "我睡不着怎么办" | 助眠入睡 |

## L7 · 相较内容库路线的显式砍项

列出被明确砍掉的方向，防止后期回流。每条附"为什么砍"溯源。

| 砍项 | 为什么砍 |
|---|---|
| 按内容类型分类的 tab / 栏目（"冥想 / 睡眠故事 / 科普"货架式） | 内容库路线 · 用户变采购员，权力分配与 Homepage 矛盾（L2）|
| 首屏 Agent 入口 / 通用问答框 | 架空三段论 + 丢掉上下文壁垒（L3.7 · L5.1）|
| 打卡 / 徽章 / 连续天数 / streak | 游戏化与临床严谨冲突；绑架用户；破坏"冷静"气质轴（L3.3）|
| "今日精选" / "热门推荐" / "编辑推荐" | 货架语言 · 与动态路径矛盾（L3.5）|
| 多目标并列让用户挑 · 首屏目标唯一 | 让用户替 App 选目标 = 权力分配反转（L3.1）|
| 多主位 CTA 并列 · 主位唯一 | 树状退化为"多选题"，三段论破碎（L3.8 · 硬约束 3）|
| 全局"浏览所有内容" / "内容库" 入口 | 等价于内容库主入口，与 `更多 ↗` 的路径语境冲突（L3.6）|
| 评分（1-5 星 / 有帮助 vs 没帮助 / 点赞）| 让用户替 App 判断；评分数据噪声大（L3.4）|
| 分享到社交平台 / 生成分享卡片 | 改善场景私人；分享破坏"不被看见"的信任感（L3.4）|
| 视频内容（瑜伽视频 / 冥想视频）| 坐看屏幕姿态与"助眠入睡"目标矛盾；v1 不出视频 |
| 评论区 / UGC / 用户笔记 | 与临床严谨冲突；审核成本高；v1 v2 都不做 |
| 心率 / HRV / 睡眠阶段图表 | Homepage 的语言（L3.3）· 破坏两个 Tab 的心智分工 |
| 默认 bgm / 自动播放音乐 | 破坏"温厚中性"声音基调（L3.3）· 用户自选 bgm 留 v2 |
| 生成式音频（TTS 朗读 / AI 原创音频）| 与"真人录音"气质约束冲突（L3.3）。"生成" = AI 挑选组合现有精品内容形成个性化 session，不指生成全新音频 |
| 目标 / 子目标的用户自定义 | v1 只做 `提神` `助眠入睡` · 自定义目标把判断权交回用户，与权力分配矛盾 |
| 付费墙 / 订阅 / 内购入口 | 不是砍项 · 是不在本 PRD 范围 · 走独立商业化 PRD |

**回流预警**：以下提议最容易在后续里程碑被"轻量化"重新引入，需警惕：

- "加一个内容库入口好不好，不做主位" → 本 PRD 否决
- "首屏加一个 Agent 悬浮按钮让用户随时提问" → 本 PRD 否决
- "给用户一个连续 7 天入睡打卡提醒" → 本 PRD 否决
- "主位卡下加一个'对这条建议评分'的小 tap" → 本 PRD 否决
- "把 Homepage 的高能时长曲线放到改善 Tab 顶部作为上下文" → 本 PRD 否决（两 Tab 心智分工）
- "让用户从 10 个目标里选今天要哪个" → 本 PRD 否决（v1 只做 2 个）

## L8 · 模块切分

### UI 模块（首屏 + 下钻）

| 中文 · 英文 | 职责 | 位置 |
|---|---|---|
| 首屏 Hero · `hero` | §1 目标 + §2 当前诊断 + §3 解法树 | 首屏·顶至中 |
| 延展位 · `path-extensions` | §4 路径相关（为什么 / 今晚 / 长期） | 首屏·底 |
| 节点消费 · `content-consumption` | 阅读器 / 播放器 + 两套完成态尾屏 | 全屏沉浸 |
| 主题深度页 · `topic-detail` | 「更多 ↗」指向的同主题延伸 | 下钻·二级 |
| Agent 追问 · `agent-followup` | 「没明白」后承接已消费内容上下文的对话 | 下钻·二级 |

### 底层引擎模块（非 UI）

| 模块 | 职责 |
|---|---|
| `path-engine` | 3 源组装：当前场景 × 历史消费 × 偏好库 → §2 §3 §4 实时生成 |
| `profile-engine` | 用户画像持续更新（Onboarding + Status 数据 + 使用行为 + Agent 识别） |

### 外部契约（不在本需求内）

- **sleep-window** —— §1 日 / 夜目标默认值切换依赖 `推荐入睡时间`。锚点待 sleep-window master PRD 完成后补。
- **Homepage / Status Tab** —— §2 当前诊断的数据输入来自 Homepage 的（分档 × 时段 × 事件流）。契约待 Homepage 补充"对外暴露的状态摘要字段"。
- **Onboarding 画像** —— `profile-engine` 静态画像源头。属独立 PRD，待立项。

### 本次不含（走独立 master PRD）

- Onboarding（首次打开画像建立）
- 用户画像长期维护机制
- 内容生产流程规范（文献 → AI 提炼 → 人工精选 + 真人录音 的 SOP）
- 音频真人录音的拾音 / 发音人选择 / 背景噪声规范
