# prd-decompose

把 master PRD 的"模块切分方式"声明展开成**可执行的模块目录骨架**。这是从"共识"到"分工"的转折点。

## 何时触发

- master PRD 的 L8 已写入、状态 `Status: Review` 或 `Locked`
- 用户明确要进入模块拆解阶段

## 输入

`prd/<feature>/` 目录路径。

## 输出

1. `prd/<feature>/modules/<name>/` 目录，每个模块含选中的空骨架文件
2. `prd/<feature>/shared/` 目录（若需要），含共享契约占位
3. 主文档.md 末尾追加"模块清单"表

## 核心行为铁律

1. **先读 master，不凭空拆**：执行前必须读 主文档.md 的 L8 和 L1-L7，拆解依据来自那里。
2. **逐模块讨论，不一次甩全表**：每个模块单独和用户过一遍，确认后再进下一个。
3. **文件组合按需，不套模板**：
   - 纯后端模块通常只要 `开发文档.md`
   - 纯视觉微调模块只要 `界面设计.md`
   - 典型 UI 模块要 `界面设计.md` + `开发文档.md`
   - PM 有调逻辑需要时加 `产品笔记.md`
   - 复杂交互/需可视化验证时加 `原型.html`
   - **给推荐、说理由、让用户拍板**
4. **契约先于实现**：若两个模块都要用同一个数据结构 / 状态模型 / Do-Don't 原则，必须抽到 shared/，不允许在两个模块 PRD 里复制粘贴。
5. **骨架不是空文件**：每个创建的 PRD 文件含锚点块 + H1 标题 + 章节占位（用 TODO 标注），这样下一阶段撰写时有结构可循。

## 执行流程

### 步骤 1 · 读 master，草拟初步模块表

读 主文档.md，基于 L8 的切分维度和"预期模块清单"，列出初步模块表：

```
| 模块 | 职责一句话 | 主要依据（L1-L7 的哪几条） |
|---|---|---|
```

给用户看这份初稿，问：**这个拆分对吗？是否需要合并 / 拆分 / 改名？**

### 步骤 2 · 逐模块共识（对每一个模块重复）

对每个模块，按以下顺序与用户过一遍：

**2.1 职责**：
- 模块负责什么？不负责什么？
- 用一句话写清楚边界。

**2.2 文件组合**：
给出推荐组合 + 理由，让用户确认或调整。推荐规则：

| 模块类型特征 | 推荐组合 |
|---|---|
| UI 重、有视觉决策 | ui-prd + dev-prd + prototype(可选) |
| 纯后端 / 数据加工 | dev-prd only |
| 纯文案 / 规则调整 | pm-notes + ui-prd(如涉及展示) |
| 复杂交互状态机 | ui-prd + dev-prd + pm-notes |
| 简单配置项 | pm-notes only |

问用户："这个模块我建议 <X>，因为 <Y>。你的判断？"

**2.3 对外契约**：
- 这个模块对外暴露什么？（数据结构 / 事件 / 状态 / 接口）
- 消费哪些共享契约？
- 如果两个模块都要用同样的东西 → 抽到 shared/，不复制

**2.4 耦合点**：
- 和哪些模块直接交互？交互方式是什么（事件 / 状态订阅 / 共享存储 / 调用）？
- 耦合是否可以解除？（如果太紧，考虑重新切分）

### 步骤 3 · 建立目录骨架

所有模块共识完成后，一次性建立：

```bash
mkdir -p prd/<feature>/modules/<name-1>/
mkdir -p prd/<feature>/modules/<name-2>/
mkdir -p prd/<feature>/shared/
```

对每个模块，创建其选中的文件，内容为骨架：

```markdown
> Master: ../../主文档.md §<章节>
> Shared: ../../shared/<契约>.md  (若消费)
> Module: <模块名>
> Role: ui | dev | pm

# <模块名> · <Role> PRD

<!-- TODO: 由 prd-<role> skill 填入 -->

## <章节 1 占位>
## <章节 2 占位>
...
```

对每个共享契约，创建 `shared/<契约>.md` 骨架，含"此契约被哪些模块消费"列表。

### 步骤 4 · 追加模块清单到 master

在 主文档.md 末尾追加一个 H2 "## 模块清单"，放一张表：

```
| 模块 | 职责 | 文件 | 对外暴露 | 消费契约 |
|---|---|---|---|---|
| hero | ... | ui,dev | ... | events-schema |
```

## 完成判据

- [ ] 每个模块都经过步骤 2 的四小步共识
- [ ] modules/ 下目录和骨架文件全部创建
- [ ] shared/ 下共享契约占位全部创建
- [ ] 主文档.md 追加了"模块清单"表
- [ ] 用户明确说"可以开始写某模块了"

满足后交还给 prd-workflow agent，等用户指定下一步写哪个模块。
