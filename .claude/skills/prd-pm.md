# prd-pm

为一个模块写**PM 自留**的 notes。读者是 PM 自己（以及未来接手的 PM）。目的是记录"为什么这样决策"和"还有什么没想清楚"，让产品逻辑可以被反复回看和调整。

**定位**：不是给工程或设计看的文档——是 PM 的工作台账。

## 何时触发

- prd-workflow 判定阶段 3 且用户要写 PM notes
- modules/<name>/产品笔记.md 已有骨架

## 输入

模块目录路径。

## 输出

该目录下的 `产品笔记.md`。

## 核心行为铁律

1. **写前必读**：主文档.md + 本模块已有的 界面设计 / 开发文档（会从这些地方吸收未决项）
2. **分批铁律**：单次 Write/Edit 最多 1 个 H2。
3. **长度目标 100-200 行**。
4. **允许非正式语气**：这是工作台账，可以用口语、可以留 "TODO 下周三见张三确认"、可以标 "我倾向 A 但还没说服自己"
5. **禁止写**：
   - 任何可以直接 copy 给工程的实现细节（→ dev-prd）
   - 任何视觉 / 文案定稿（→ ui-prd）
   - Master 已经锁定的共识（不重复）
6. **用时间戳标注决策**：每次重要决策加日期，便于回溯。

## 章节骨架

```
# <模块名> · PM Notes

> 锚点块

## 1. 逻辑状态表（PM 视角）
## 2. 决策日志
## 3. 未决项（本模块）
## 4. 待验证 hypothesis
## 5. 给未来我的备忘
```

## 每节写作指引

### §1 逻辑状态表（PM 视角）

区别于 ui-prd §2 的"UI 状态"和 dev-prd §3 的"技术状态机"——这里是**产品逻辑状态**：

```
| 产品状态 | 什么情况进入 | 用户会看到什么（摘要） | 我为什么选这样 |
|---|---|---|---|
| 首次 onboarding | 用户第一次进 | 简化欢迎态 | 不想一来就信息过载 |
| 日常态 | 有 >=1 天数据 | 完整 hero + timeline | 核心价值在这 |
| 空数据态 | 新用户但已过 onboarding | 引导创建第一条 | 避免用户卡死 |
```

**表头最后一列"我为什么选这样"是这份文档的灵魂**——记录产品思考。

### §2 决策日志

按时间倒序记录重要产品决策：

```
### 2026-04-22 · 决定 Hero 不显示数字
- 背景：设计给了两版，数字版/文字版
- 权衡：数字版更精确但冷，文字版更温但模糊
- 决定：文字版
- 依据：master L4 "让用户感到被理解而非被评估"
- 风险：部分用户会要"给我看数据"——预留"查看详情"二级入口
```

### §3 未决项

汇总从 ui-prd §7 和 dev-prd §10 来的未决项 + PM 自己新发现的：

```
- [ ] [UI] 空态的插画风格 — 待和设计讨论（从 ui-prd §7）
- [ ] [逻辑] 24 小时无操作是否要推送提醒 — 待用研  
- [ ] [PM] 高能时长的周汇总要不要放到 hero — 我倾向不放但没验证
```

加方括号分类：`[UI]` `[工程]` `[逻辑]` `[PM]`。

### §4 待验证 hypothesis

本模块上线后要验证的产品假设：

```
- **假设 1**：用户会在早晨 6-9 点打开这个模块记录睡眠
  - 验证方式：看 hero.impression 埋点的时段分布
  - 预期结果：该时段 impression > 30%
  - 如果不成立：重新考虑模块入口位置

- **假设 2**：...
```

### §5 给未来我的备忘

随便写的 "future-me will thank me"：

```
- 这个模块的交互是我和设计师吵了 3 轮的结果，下次想改之前先看 decision 日志 §2 的 2026-04-22 条
- pm-notes 不要给工程看，他们只关心 dev-prd
- events-schema 的 impact 字段值域我还想再调，但等积累 2 周数据再说
```

## 完成判据

- [ ] §1 逻辑状态表每行的"为什么"列非空
- [ ] §2 至少有 1 条决策日志（哪怕只是"沿用 master L3 的约束"）
- [ ] §3 §4 可以为空但要显式标 "暂无"
- [ ] 没有任何内容会被工程或设计当成施工图

完成后交还给 prd-workflow，可以走 prd-review（pm-notes 的审查主要是"和 master 冲突"和"和 ui/dev 有无逻辑矛盾"）。
