# prd-iterate

## 路由判定

按顺序自问：

- **Q1** 新要求动摇了"是什么 / 给谁解决什么 / 怎么解决"的宏观共识？→ 调 `prd-master` 改主文档（罕见）
- **Q2** 新要求是个职责完全独立的子需求？→ 调 `prd-module` 新建一份模块 md
- **Q3** 默认 → 写迭代版本（最常见）

不确定就告诉用户："我倾向走 X，因为 Y。同意吗？"

## 迭代版本骨架

`prd/<feature>/迭代/v<N>-<主题>.md`：

```markdown
# v<N> · <主题一句话>

> Status: Draft | Locked
> Base: 主文档.md / <模块>.md

## 改了什么
- <一句话差异>

## 不变 / 砍掉
- <明确不动 / 被砍 · 一句话>

## 流程 / 状态 / 边界（仅有变化的部分 · 按需）
（mermaid 只画 diff 后那段；状态只列新增 / 改的；边界只列新增的）
```

`<N>` 从 v2 开始（v1 = 老文档）；`<主题>` 用动词短语。

## 关键动作

1. **不动老文档**：哪怕老文档某条已过时——只在新迭代里写"这条砍掉"。回看靠按时间序读 v1 → vN 拼真相。
2. **≤ 300 字**：超即说明用户其实想做两件事，主动建议拆成 v<N>-A + v<N+1>-B。
3. **持续叠加预警**：同 feature 已有 v2/v3 时用户又来加东西、且新主题与现有 v<N> 不重合 → 主动建议开 v<N+1>，不撑长 v<N>。
4. **更新 html**：迭代落稿后回到 `prd/<feature>/原型.html`，把变化反映到演示。
5. **完成后**：`Status: Locked` → 调 `prd-host`。
